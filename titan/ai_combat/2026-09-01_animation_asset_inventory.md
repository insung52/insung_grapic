## 0. 먼저 알아둘 구조 3가지

디자이너 입장에서 목록만 보면 헷갈릴 수 있는 부분:

1. **아군과 적군은 같은 애니메이션을 공유한다.** 블렌드스페이스도 `BS_ally_kadex*` 하나를 양쪽이
   같이 쓴다. 적군 전용 애셋은 낙하산 착지·사망 계열뿐. (스켈레톤은 다르지만
   `CompatibleSkeletons` 설정으로 리타겟 없이 재생됨.)
2. **애셋 이름이 직관과 반대인 것이 하나 있다** — `AS_RifleAim`이 **총 내린** Idle,
   `AS_RifleIdle`이 **조준** Idle이다. 문서·코드 전반에서 이 이름 그대로 쓰이므로 주의.
3. **이동은 코드가 시키고 애니메이션은 제자리 사이클만 재생한다**(루트모션 없음). 그래서
   "몸이 보는 방향"과 "실제 이동 방향"이 따로 놀 수 있고, 그 차이를 블렌드스페이스의 `Direction`
   축이 받아서 스트레이프/뒷걸음 모션으로 바꿔준다. 이게 아래 여러 연출의 기반이다.

## 1. 로코모션 — 블렌드스페이스 3종

이동 애니메이션은 전부 블렌드스페이스로 재생된다. 가로축 `Speed`(0~600), 세로축 `Direction`
(-180°~180°). **축 300 = 걷기, 축 600 = 뛰기**가 앵커이고 그 사이는 자동 보간된다.

### 1-1. `BS_ally_kadex` — 서서 이동 (조준/총내림 공통) ✅ 확인 완료

| Speed 축 | Direction | 시퀀스 |
|---|---|---|
| 0 (정지) | 전 방향 공통 | `AS_RifleIdle` |
| 300 (걷기) | 0° / ±45° / ±90° / ±135° / 180° | `AS_Aim_Walk_Fwd_2`, `AS_Aim_Walk_Fwd_Left`, `AS_Aim_Walk_Fwd_Right_2`, `AS_Aim_Walk_Left_2`, `AS_Aim_Walk_Right`, `AS_Aim_Walk_Bwd_Left`, `AS_Aim_Walk_Bwd_Right`, `AS_Aim_Walk_Bwd` |
| 600 (뛰기) | 0° / ±45° / ±90° / ±135° / 180° | `AS_Jog_Fwd_2`, `AS_Jog_Fwd_Left`, `AS_Jog_Fwd_Right`, `Run_Left`, `AS_Jog_Right_2`, `AS_Jog_Bwd_Left_2`, `AS_Jog_Bwd_Right_2`, `AS_Jog_Bwd_2` |

> ⚠ 600축 좌측(-90°)만 `Run_Left`가 들어가 있음(나머지 7방향은 전부 `AS_Jog_*` 계열).
> **같은 계열의 `AS_Jog_Left_2`가 프로젝트에 존재하는데 어디에도 안 쓰이고 있어**, 좌측만 다른
> 애셋이 꽂힌 것은 실수일 가능성이 높다. 좌우 사이드스텝의 느낌이 다르게 보인다면 이 지점이 원인.

### 1-2. `BS_ally_kadex_Crouch` — 숙여서 이동 ✅ 확인 완료

| Speed 축 | 시퀀스 |
|---|---|
| 0 (정지) | `AS_Crouching` (전 방향 공통) |
| 300 (걷기) | `AS_Crouch_Aim_Walk_Fwd_2`, `_Fwd_Left`, `_Fwd_Right_2`, `_Left`, `_Right`, `_Bwd_Left_2`, `_Bwd_Right_2`, `_Bwd` |
| 600 (뛰기) | `AS_Crouch_Aim_Run_Forward`, `_Left_2`, `_Right_2`, `_Backward_2` (4방향만, 대각선 없음) |

> ⚠ `AS_Crouch_Aim_Run_Forward` 샘플에만 **재생 배속 1.3배**가 걸려 있음. 원본이 실제 이동속도보다
> 느려서 넣은 보정으로 보임 — 원본을 교체하게 되면 이 값도 같이 봐야 함.
> ⚠ 숙여 뛰기는 대각선 4방향(±45°, ±135°)이 없어서 인접 방향으로 보간됨.

### 1-3. `BS_ally_kadex_Lowered` — 총 내리고 이동 ✅ 확인 완료 / ⚠ **현재 미사용**

다른 둘과 달리 **방향 축이 없는 1D 블렌드스페이스**(전진 전용, 3개 샘플뿐):

| Speed 축 | 시퀀스 |
|---|---|
| 0 (정지) | `AS_RifleAim` (총 내린 Idle) |
| 300 (걷기) | `AS_Walking` |
| 600 (뛰기) | `AS_Lowered_Run_Fwd` |

> ⚠ **확정: 이 블렌드스페이스는 현재 아무도 쓰지 않는다.** 아군·적군 애님 블루프린트의
> `LoweredLocomotion` 상태를 노드 단위로 확인한 결과, 둘 다 **`BS_ally_kadex`(서서 조준용)** 를
> 물고 있다(그 상태 안에는 블렌드스페이스 노드가 하나뿐이라 다른 경로도 없음).
>
> **결과적으로 총을 내리고 걸을 때도 "조준 자세" 시퀀스가 재생되고 있다.** 1차 전투지로
> 서행하는 구간이 여기 해당한다. 다만 이 상태로 이미 여러 차례 육안 확인을 거쳤고 크게
> 어색하지 않았던 점, `BS_ally_kadex_Lowered`는 전진 1방향뿐이라 지금의 사주경계(옆걸음·뒷걸음)
> 연출을 아예 표현할 수 없다는 점 때문에, **단순 교체는 오히려 퇴보**다.
> → 총 내린 상태의 8방향 세트가 갖춰지기 전까지는 현 상태 유지가 맞다(6절 추가 요청 후보).

## 2. 상황별 단발 동작 (슬롯 재생)

로코모션 위에 겹쳐서 재생되는 것들. 슬롯별로 나뉜다.

| 슬롯 | 언제 | 재생 애셋 | 적용 대상 |
|---|---|---|---|
| `FireRecoil` | 사격 시 반동 | `Firing_Rifle_Anim_2` | 아군·적군 |
| `ReloadSlot` | 재장전 | `AS_Reloading` | 아군·적군 |
| `DefaultSlot` | 낙하산 착지 | `AM_Falling_To_Landing` / `AM_Hard_Landing` | 적군 |
| `UpperBodySlot` | (예약) 상체 전용 | — 현재 미사용 | 적군 |

> ⚠ **`DefaultSlot` 경로가 죽어 있음 — 착지 몽타주가 화면에 안 나오고 있을 가능성이 큼.**
> 이 슬롯이 지나가는 레이어드 블렌드 노드의 본 필터가 `Spine / 깊이 -1`로 설정돼 있는데,
> 엔진 규칙상 깊이가 음수면 **모든 본의 가중치가 0**이 된다(= 몽타주가 최종 포즈에 반영 안 됨).
> `AM_Falling_To_Landing`/`AM_Hard_Landing` 둘 다 `DefaultSlot`을 쓰는 것으로 확인됨.
> 개발 쪽 미해결 항목(7절).
>
> **피격 리액션은 몽타주를 쓰지 않는다** — `AS_Hit_Reaction`/`AM_Hit_Reaction` 애셋은 있으나
> 재생하는 곳이 없고, 4-5절의 코드 스프링 방식으로 완전히 대체됐다.
> `UpperBodySlot`은 상체만 얹는 경로로 이번에 신설(본별 가중치 마스크 포함)했으나 현재 재생하는
> 것이 없음 — 상체 전용 동작이 생기면 바로 쓸 수 있다.

## 4. 애니메이션 대신 **코드로 구현한 것들**

디자이너 입장에서 "이건 왜 애니메이션 요청이 없지?" 싶은 것들이 여기 해당한다. 전부 시퀀스 없이
런타임 계산으로 만들어지므로 **추가 제작이 불필요**하다.

### 4-1. 좌우 기울임 (Lean)
엄폐물에서 몸을 좌/우로 기울이는 동작. 전용 시퀀스 없이 척추 본 각도를 코드로 직접 돌린다.
(`LeanAlpha` -1 ~ +1)

### 4-2. 조준 상하 각도 (Aim Pitch)
위/아래를 조준할 때 상체가 젖혀지는 것. `Spine2` 본 회전을 직접 조정하고 목·머리가 따라온다.
총구가 목표를 정확히 향하도록 하는 **총구 기준 좌우 보정**도 코드 처리(블렌드스페이스 포즈마다
총구가 몸통 정면에서 틀어지는 것을 매 프레임 역산해서 몸 각도로 보정).

### 4-3. 1차 전투지 서행 중 주변 경계 ★
**전용 "두리번거리기" 애니메이션을 쓰지 않는다.** 대신 몸이 보는 방향을 이동 방향과 분리해서,
지정된 경계 방향을 중심으로 ±60° 범위를 **펄린 노이즈로 천천히 불규칙하게 훑는다**. 몸이 돌아간
만큼 블렌드스페이스의 `Direction` 축이 바뀌므로, **기존 스트레이프/뒷걸음 시퀀스가 자동으로
재생되면서 "몸은 옆을 경계하고 발은 목적지로 가는" 그림**이 나온다.

> 전용 몽타주(`AM_Enemy_Looking_Around_Montage_Base` 등)로 만드는 방향을 먼저 시도했다가
> 폐기했다. 보유한 둘러보기 애셋들이 **전부 발부터 머리까지 같이 도는 전신 모션**이라, 웅크린
> 채 걷는 자세와 겹치면 하체 가중치를 낮추면 고개만 까딱하고, 높이면 걷다 말고 일어서버렸다.
> 상체만 돌아보는 모션이 따로 있으면 품질이 더 올라가지만 **필수는 아님**.

경계 이동 중에는 고개가 너무 숙여지지 않도록 상체 각도도 코드로 살짝 들어올린다(4-2와 같은 방식).

### 4-4. 사격/엄폐 순환, 경계사격하며 이동
개체마다 랜덤한 시간으로 "사격 ↔ 엄폐" 자세를 오가고, 전투지로 돌진할 때는 "몇 초 경계사격하며
천천히 이동 ↔ 몇 초 전력 이동"을 번갈아 한다. 자세 전환은 위 로코모션 블렌드스페이스와
`IsKneeling` 같은 상태값 조합으로 만들어지며 전용 시퀀스가 없다.

### 4-5. 피격 반응 (비살상) ★
피격 시 몸이 움찔하는 반응을 **물리 시뮬레이션도 몽타주도 아닌 순수 계산(감쇠 스프링)** 으로
만든다. 총알이 날아온 방향과 **맞은 부위**를 실제로 판정해서:
- 몸통/양다리/양팔/골반에 각각 독립된 스프링이 걸리고, 맞은 부위는 강하게·인접 부위는 약하게
- **지렛대 효과**: 팔다리 끝을 맞을수록 그 팔다리가 크게 꺾이고, 관절 근처는 조금만
- **관성(채찍) 효과**: 몸통 중심을 맞으면 골반이 밀리면서 팔다리가 반대로 튀어나옴
- 골반은 회전이 아니라 위치가 밀렸다 돌아옴

애니메이션 위에 얹히는 방식이라 걷는 중이든 엄폐 중이든 자세와 무관하게 자연스럽게 동작한다.
(기존 `Hit_Reaction` 몽타주가 서 있는 자세로만 만들어져 있어 웅크린 상태에서 벌떡 일어나던
문제를 대체한 것.)

### 4-6. 사망 — 액티브 랙돌
사망 애니메이션을 재생하지 않고 **물리 랙돌로 즉시 전환**한다. 죽는 순간의 이동 관성과 총알
방향 충격이 함께 적용되어, 뛰던 중에 죽으면 그 방향으로 쓰러진다. 무기도 손에서 떨어져 나간다.
→ **사망 모션 시퀀스는 제작 불필요.**

### 4-7. 이동 속도 ↔ 발걸음 속도 매칭
캐릭터의 실제 이동 속도에 맞춰 블렌드스페이스 축 값을 계산해서, 걷는 속도를 낮추면 발도 그만큼
느리게 움직인다(발 미끄러짐 방지). 기준값은 **걷기 200 / 뛰기 600 / 숙여걷기 200 / 숙여뛰기 400
(cm/s)** 이며, 애니메이션 원본이 이 속도에 맞춰져 있다는 전제로 맞춰져 있다.

> 새 로코모션 시퀀스를 받을 때 **실제 이동 속도를 이 값에 맞춰 제작**해주시면 별도 보정 없이
> 바로 맞는다.

### 4-8. 기타 코드 처리
- **제자리 회전**: 전용 turn-in-place 모션 없이 캡슐을 천천히 회전시키는 관성 시스템으로 대체
- **분대별 이동 경로**: 적 15명을 3분대로 나눠 서로 다른 경로로 이동(내비메시 가중치)
- **왼손 무기 파지**: IK로 총 손잡이에 붙임(시퀀스에서 손 위치가 조금 달라도 자동 보정)

## 5. 보유 중이나 현재 재생되지 않는 애셋

정리·재활용 판단이 필요한 것들. **삭제 전 개발팀 확인 필요**.

| 애셋 | 비고 |
|---|---|
| `AM_Enemy_Death2`, `AM_Enemy_Death_Montage`, `AS_Enemy_Death`, `AS_Enemy_Death2` | 사망이 랙돌로 대체되면서 미사용 |
| `AM_Enemy_Looking_Around_Montage(_Base)`, `AS_Enemy_Looking_Around` | 착지 직후 경계 상태값으로만 쓰임, 경계 이동에는 미사용(4-3 참고) |
| `AS_Hit_Reaction`, `AM_Hit_Reaction` | **확정 미사용** — 코드 스프링 방식으로 대체(4-5) |
| `BS_ally_kadex_Lowered`(블렌드스페이스), `AS_Walking`, `AS_Lowered_Run_Fwd` | **확정 미사용** — 총 내린 이동에도 `BS_ally_kadex`가 재생 중(1-3절) |
| `AS_Jog_Left_2` | **확정 미사용** — 600축 -90°에 `Run_Left`가 대신 들어가 있음(1-1절) |
| `Crouch_Torch_Idle_02_Anim` | 경계 이동용으로 검토했다가 미채택(전신 모션) |
| `AS_Cover_Pop-up` / `AS_Cover_Pop-down` | 엄폐 팝업 — 현재 자세 전환이 블렌드스페이스로 처리되어 미사용으로 추정 |
| `AS_Left_Turn` / `AS_Right_Turn` | 제자리 회전 — 코드 회전으로 대체(4-8) |
| `AS_Weapon_Raise` / `AS_Weapon_Lower` / `AS_Aim_To_Down` | 총 들기/내리기 — 현재 상태 전환 크로스페이드로 처리 |
| `Run_Forward_Anim_2` 계열, `AS_Run`, `AS_Run2`, `AS_Walking` | 구버전/튜토리얼 잔여 애셋으로 추정 |
| `AS_Crouch_Look_Around`, `AS_Inspecting`, `AS_Stopsign` | 아군 수신호/살펴보기 계열 — 일부만 사용 중 |

> ⚠ "미사용으로 추정" 항목들은 애님 블루프린트 상태머신 내부까지 전수 확인한 결과가 아니므로,
> 실제 삭제 전에는 개발 쪽에서 참조 검사를 한 번 돌려야 함.

## 6. 디자인팀이 알아두면 좋은 제작 규칙 (요약)

`../ally_animation_request.md`의 "기술 요구사항"과 동일하며, 여전히 유효하다:

- **루트모션 없이 제자리(in-place)** — 이동은 코드가 시킴
- **루프 가능** (시작 포즈 = 끝 포즈)
- **8방향 세트는 몸통이 아니라 다리만 방향이 바뀜** — 항상 정면(조준 방향)을 본 채 스텝만 그 방향
- **허리(Spine)의 상하/좌우 무게중심 이동이 실제로 들어가 있어야 함** — 고정되어 있으면 미끄러져 보임
- **이동 속도 기준**: 걷기 200 / 뛰기 600 / 숙여걷기 200 / 숙여뛰기 400 (cm/s)
