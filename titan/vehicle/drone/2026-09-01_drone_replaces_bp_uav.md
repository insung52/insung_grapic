# 새 드론이 구 BP_UAV를 대체 — 자율비행부터 리플리케이션까지

2026-09-01 / 완료 / 물리 드론(`ADronePawn`)에 자율비행·짐벌·사운드·바람·단계별 탐지·시나리오·리플리케이션을 이식해 구 `AUAVPawn`/`BP_UAV`를 대체. 2프로세스 실환경 검증만 남음.

이 문서는 **작업 경과와 그 과정에서 겪은 함정**의 기록이다. "드론이 지금 어떻게 동작하는가"는
같은 폴더의 `drone_flight_dev_guide.md`(에버그린 레퍼런스)를 볼 것.

선행 작업: 2026-08-27 구동계 + 수동 조종 구현(같은 가이드 1~10절).

## 1. 구 `BP_UAV` 대비 갭 분석 → 무엇을 이식했나

2026-08-29에 구 UAV가 갖고 있던 기능을 전수 비교한 결과와 처리 방침:

| 구 UAV 기능 | 처리 | 비고 |
|---|---|---|
| 자율비행(직선 이동) | **재설계 이식** | `EnemyCube` 태그 직선 → 아티스트가 그린 스플라인 경로로 교체 |
| 짐벌 카메라 + 씬캡쳐 영상피드 | 이식 | BP CineCamera + 런타임 SceneCapture, 구 UAV와 같은 패턴 |
| 짐벌 자동 정찰(낙하산 관측) | **이식 + 승격** | 구현은 비슷하지만 역할이 바뀜 — 아래 3절 |
| 상태 패널 HUD(`UStatusHUDComponent`) | 이식 | 고도/속도/방위만 실제 연동, 나머지는 더미 생성기 |
| 탐지(`UTargetDetectionComponent`) | **이식 + 확장** | 진영 필터 + 최소 화면 크기 신설, 단계별 공개 |
| 피아식별 표식(`UDetectableTargetComponent`) | 이식 | 드론 자신이 아군으로 잡히게 |
| RTSP 스트림 | 이식 | mount `selfdefense/uav_gimbal` |
| 시나리오 연동(DT 트리거/이펙트) | **이식 + 재배선** | 3절 |
| 리플리케이션 | **재설계** | 서버 권위 → 클라이언트 권위, 5절 |
| 위젯(`SelfDefenseMonitor1Widget`) | 이식 | `UAVRef` 타입을 `ADronePawn`으로 교체, 줌 버튼 직결 |
| 지형 회피(라인트레이스로 추력 보정) | **폐기** | 스플라인을 지형 위로 그리는 것으로 대체 |
| `EnemyCube` 태그 목적지 | **폐기** | 스플라인 경로가 목적지 |
| 적 탐색 단계 / 아군 집결 대기 | **폐기** | 낙하산 관측 하나로 통합(3절) |

구 `AUAVPawn`/`BP_UAV`는 아직 지우지 않았다 — 시나리오 연동 지점이 전부 "드론 우선, 없으면 구
UAV" 폴백 구조라 공존한다. 2프로세스 검증이 끝나면 폴백과 구 클래스를 함께 걷어낸다.

## 2. 자율비행 — UGV 자율주행에서 가져온 것과 안 가져온 것

UGV `BP_UGV_Vehicle_new` 작업에서 검증된 유도 구조(Pure Pursuit, 제동 곡선)를 이식했다.
다만 **UGV 로직을 그대로 갖다 붙였다가 세 번 크게 틀렸다** — 아래 4절.

가져온 것:
- Pure Pursuit 당근점 추종(`vehicle/ugv/` 주행 가이드)
- `허용속도 = √(통과속도² + 2·감속도·거리)` 제동 곡선
  (`vehicle/ugv/2026-08-22_ugv_corner_braking_dev_guide.md`)
- 꺾임각 → 통과속도 **선형** 매핑(유계라 폭주가 구조적으로 불가능)
- 곡률 측정 구간과 샘플 간격의 분리("커브 묶기")

안 가져온 것:
- **브레이크 개념.** 드론은 거버너 출력을 목표 속도로 두고 속도 루프에 넣으면 뒤로 기울어
  감속하는 게 저절로 나온다. UGV보다 오히려 단순하다.
- **NavMesh / 장애물 회피.** UGV의 `MinCornerSpeed`는 숲길 장애물 회피용이라 드론엔 성격이
  다르다(드론에서는 단순 커브 속도 하한으로만 씀).

핵심 설계 원칙은 "**위치를 직접 쓰지 않는다**" — 오토파일럿은 사람과 똑같은 4채널 스틱 입력만
만들고 물리는 손대지 않는다. 이걸 지켰기 때문에 "자연스러운 스로틀/회전"을 따로 만들 필요가
없었다.

## 3. 시나리오 재배선 — 낙하산 관측이 UGV 출발 트리거

사용자 요구(2026-08-29): **낙하산 관찰 단계는 무조건 있어야 하고, 그 관찰 성공이 UGV 출발
트리거가 된다.** 구 흐름에 있던 "UAV 적 탐색 단계"와 "아군 집결 대기"는 제거.

바뀐 전체 흐름:

```
BeginScenario
  → (3s) BeginUAVMission        드론이 uavpath 스플라인으로 이륙(5초 상승) → 순항 → 도착
  → 도착 시 드론 스스로 탐지단계 FriendlyOnly → PlusEvidence (낙하산이 보이기 시작)
  → 짐벌 자동정찰: 좌우 스윕 5초 → 낙하산 스냅 + 줌인 2.5배 → 5초 관찰
  → UAVParachuteObserved         ★ UGV 1차 목적지로 출발
  → RevealEnemies
  → UGV RCWS가 적 포착(EnemyDetected)
  → EnableDroneEnemyDetection    탐지단계 → All (적군까지 전부)
  → (2s) UAVEngagementZoomOut    아군 + UGV + 적군이 한 화면에 들어오게 광각/조준 자동
```

신설한 것(`UI/ScenarioStepTypes.h`):
- 트리거 `UAVParachuteObserved`
- 이펙트 `EnableDroneEnemyDetection`, `MoveDroneToPath`
- 행 필드 `FName UAVPathId`

DT(`/Game/Scenario/DT_ScenarioSteps_ThreeStage`) 변경:
- `UAVSpotted` 트리거 `UAVEnemyDetected` → **`UAVParachuteObserved`**
- `DroneSeeEnemies` 행 신설(선행 `UGVSurveillance`, 트리거 `EnemyDetected`)
- `DroneWideView` 행 신설(선행 `DroneSeeEnemies`, 2초 후)
- `UAVDetectionOff` 행은 `bEnabled=false`로 내림 — 단계별 탐지가 그 역할을 대신함

`UAVEngagementZoomOut`의 프레이밍 지점 목록에 **UGV를 추가**했다(`ResolveUGVPawn`) — 예전엔
아군만 넣어서 정작 교전 주체인 UGV가 화면 밖으로 나갔다.

## 4. 겪은 함정

### 4.1 짐벌이 팬은 되는데 짐벌 시점에선 안 먹음 (2026-08-28, 2회 재작업)

증상이 기묘했다 — **밖에서 보면 좌우 회전은 잘 도는데 위아래가 이상한 방향으로 돌고, 짐벌
시점에서 보면 위아래는 되는데 좌우가 안 먹었다.** 원인이 두 개 겹쳐 있었다:

1. 델타 쿼터니언을 **오른쪽에** 곱해서(본 로컬 축) 틸트 축이 엉뚱해짐 → 컴포넌트 공간이므로
   왼쪽에 곱해야 함.
2. `SetBoneRotationByName(ComponentSpace)`는 **델타가 아니라 절대 CS 방향**을 받는데,
   CamPitch에 부모 yaw를 빼고 넘겨서 엔진이 부모의 yaw를 상쇄해버림.

구 UGV/UAV가 같은 문제를 어떻게 풀었는지 확인하고 나서야 정리됐다. 상세는 가이드 12.2절.

### 4.2 자율주행 속도가 9~10km/h에 고정 (2026-08-29)

45km/h로 설정했는데 tilt가 4~5°밖에 안 나오고 속도가 10km/h에 붙어버렸다. **Pure Pursuit을
위치 목표로 잘못 배선한 것**이 원인:

```
목표속도 = 전방주시거리(4m) × PositionP(0.7) = 2.8 m/s = 10km/h
```

거버너가 계산한 속도가 아예 안 쓰였고, 전방주시거리가 속도에 비례하니 **저속 → 짧은 당근 →
더 낮은 목표속도**의 자기강화 루프까지 있었다. 당근은 *방향만* 주고 크기는 거버너가 준다는
Pure Pursuit의 원형으로 되돌렸다(`bFlyThroughAtSpeed`).

같이 걸려 있던 두 번째 원인: 가속도 상한(2.5 m/s²)이 45km/h에서 항력을 이기는 데 필요한
2.55 m/s²보다 낮았다. 상한을 항력 피드포워드 **앞으로** 옮기고 5.0으로 올려 해결.

> 교훈: "UGV에서 검증된 로직"을 옮길 때 **구조가 아니라 의미**를 옮겨야 한다. 같은 이름의
> 게인이 다른 역할을 하는 걸 못 보고 배선했다.

### 4.3 45km/h에서 아예 안 줄어듦

커브 통과속도를 `√(측면가속도/곡률)`로 계산했는데 이 식은 상한이 없어서, 반경 39m보다 커지면
순항속도를 넘어가 사실상 감속이 안 걸렸다. 게다가 곡률을 2.5m 구간으로 재서 완만한 롱커브가
각도 ≈0으로 나왔다. UGV의 **유계 선형 매핑**으로 교체하고 곡률 측정 구간(10m)을 샘플
간격(2.5m)에서 분리해 해결.

### 4.4 바람에 너무 잘 버팀 (사용자가 먼저 지적)

항력 피드포워드가 **대기속도**(속도−바람) 기준이라, 코드가 바람 값을 직접 읽어 지연 없이
완벽히 상쇄하고 있었다. 실제 드론엔 풍속계가 없다 — 바람은 밀린 **결과로만** 감지한다.
피드포워드를 대지속도만 쓰도록 바꾸고 `VelocityI` 적분기(0.5)를 추가해서, 돌풍마다 눈에 보이게
흔들렸다가 기울여 버티는 그림이 나오게 했다.

### 4.5 낙하산을 찾았는데 UGV가 안 감

드론은 낙하산을 찾아 줌인까지 하는데 UGV가 출발을 안 했다. `UAVSpotted` 행의 트리거가 아직
`UAVEnemyDetected`(적 감지)로 남아 있었던 것 — 행 설명은 "UAV가 낙하산 발견"인데 실제 판정이
달랐다. MCP로 `UAVParachuteObserved`로 교체.

그 전 단계에서는 레벨 인스턴스의 `ParachuteActor`가 비어 있어 정찰이 아예 시작되지 않는
문제도 있었다. 진단 로그를 넣었는데 **null 체크가 그 로그를 부르는 코드를 감싸고 있어서 영원히
도달하지 않는** 상태였다 — 1회성 경고(`bWarnedMissingParachute`)로 바깥에 꺼냈다.

### 4.6 유니티 빌드 상수 재정의 (C2086)

`DroneAutopilotComponent.cpp`를 만들 때 `DroneFlightComponent.cpp`의 단위 상수 블록을 복사해
왔는데, 둘 다 익명 네임스페이스였다. UE 유니티 빌드가 두 `.cpp`를 한 번역 단위로 합치면서
익명 네임스페이스도 합쳐져 `CmPerMeter` 재정의 오류가 났다. 파일별로 컴파일될 땐 안 드러나서
한동안 잠복해 있었다. `DroneFlightComponent.h`의 `namespace DroneUnits`로 통합.

## 5. 리플리케이션 — 클라이언트 권위로 결정

**2대 PC 2프로세스이고, 드론을 조종하는 쪽이 서버(UGV축)가 아니라 클라이언트(자체방호축)다.**
그래서 서버 권위로 하면 입력 지연이 그대로 드러난다.

엔진의 Chaos Resimulation(예측+롤백)을 먼저 조사했으나 채택하지 않았다 — UE5.8에서 WIP이고
`bTickPhysicsAsync`를 요구하는데, 그걸 켜면 68ms까지 낮춰둔 RTSP 종단 지연이 +33ms 늘고 튜닝이
끝난 UGV Chaos 차량 거동까지 바뀐다. 전용 LAN의 전시 장비 2대라 클라이언트를 신뢰해도 위협
모델상 문제가 없다.

설계 상세와 배선은 `replication/2026-09-01_drone_client_authoritative.md`,
동작 요약은 가이드 15절.
