# 드론 교전 관측 이동 — 스플라인 위 자동 관측 지점 선정

2026-09-05 / 완료 / 교전 중 드론이 스플라인 위에서 "지금 전황을 가장 잘 보여주는 지점"으로 스스로 이동. 프레이밍을 TargetDetection에서 분리하고, 유도 루프의 저감쇠 진동·적분 와인드업 등 구조적 결함 8건 해결.

이 문서는 **작업 경과와 겪은 함정**의 기록이다. "지금 어떻게 동작하는가"는 같은 폴더
`drone_flight_dev_guide.md` 16절(에버그린 레퍼런스)을 볼 것.

선행: `2026-09-01_drone_replaces_bp_uav.md`(구 BP_UAV 대체).

---

## 1. 왜 필요했나

구현 직전 상태는 "경로 끝에 도착해 정지비행하며 짐벌만 돌린다"였다. 그런데 **짐벌은 각도만
바꿀 뿐 거리를 못 줄인다.** 교전이 2·3차 전투지로 옮겨가면 화면에 "전원이 담기긴 하는데
아무것도 분간이 안 되는" 그림이 남았다.

기체가 직접 다가가야 하는데, 이 드론에는 지형 회피가 없다(스플라인이 그 역할을 대신한다).
그래서 **자유비행이 아니라 "아티스트가 그려준 선 위에서 가장 잘 보이는 지점"** 을 고르는
구조로 갔다 — 안전이 저작 단계에서 보장된다.

---

## 2. 최종 구조

```
시나리오 세트(Zone1/2/3)  →  프레이밍 대상 (레지스트리 직결)
                                    │
                    ┌───────────────┴───────────────┐
                    │                               │
        폰: 관측 지점 선정                   짐벌: 조준 + 줌
        (화각/부감 제약 만족)                (각도상 중점 + 필요 화각)
                    │
                    ▼
        자율비행: 유도점 흘려보내기 → 속도 피드포워드 + 위치 P → 스틱
```

역할 분담이 핵심이다. **"어디서 볼지"는 렌즈·화각을 아는 폰이 정하고, 자율비행은 지시받은
스플라인 진행거리까지 부드럽게 날아가는 것만 책임진다.**

## 3. 겪은 함정 (시간순)

### 3.1 대리 지표로 목표 함수를 잘못 세움

처음 짠 점수 함수가 "**내가 정한** 이상적 거리 250m·고도 80m에 얼마나 가까운가"였다. 대상들의
실제 배치(퍼진 정도, 화각에 들어오는지)를 아예 안 봤다 — 11명이 300m로 흩어져 있든 20m에
뭉쳐 있든 점수가 같았다. 사용자 지적으로 **실제 프레이밍 결과**(그 지점에 카메라를 놓았을 때의
필요 화각·조준 부감)로 갈아엎었다.

> 교훈: "무엇을 최적화할지"를 대리 지표로 바꿔 놓고 그 위에 가중치·마진을 얹으면, 튜닝을
> 아무리 해도 원하는 결과가 안 나온다.

### 3.2 연속 최적화 → 래칫

"가장 점수 좋은 지점"을 계속 찾게 했더니 **3분 반 동안 25m씩 21회** 뒤로 기어갔다. 연속 점수엔
항상 "조금 더 나은 점"이 존재하기 때문. 체류시간·점수마진 같은 반창고를 붙이다가, 결국
**제약 만족** 방식으로 바꿨다 — 조건을 만족하는 동안은 후보 탐색 결과를 보지도 않는다.
안정성이 튜닝이 아니라 구조에서 나온다.

### 3.3 클램프된 화각으로 초과량을 판정

```cpp
OutRequiredFOVDegrees = FMath::Clamp(..., Min, Max);          // 실제 150°든 90으로 잘림
Shortfall += 2.0 * (RequiredFOV - MaxFOV) / MaxFOV;           // 90 - 90 = 0. 언제나.
```

초과 벌점이 **항상 정확히 0**이었다. 결과가 두 겹으로 나빴다 — 화각이 터졌는데도 "완전 만족"
으로 오판했고, "화각 안 되면 뒤로 물러난다"가 아예 작동하지 않았다. 클램프 **전** 원본을 따로
반환하게 고쳤다.

### 3.4 판정 문턱이 하나뿐이라 경계에서 진동

부감이 -43~-45°를 오가는데 밴드 경계가 정확히 -45°라, **1초마다 만족/불만족이 뒤집혔다**
(`차선 선택` ↔ `조건 회복`이 교대로 로그에 찍힘). 슈미트 트리거로 분리 — 목적지로 고를 땐
엄격하게(화각 여유 10%, 밴드 안), 지금 자리를 유지할지 볼 땐 느슨하게(밴드 ±8°).

### 3.5 TargetDetection을 프레이밍 입력으로 씀

적군 위치를 짐벌 카메라의 탐지 결과에서 가져왔더니 **순환 의존**이 생겼다:

```
줌아웃 → 대상이 화면에서 작아짐 → 겉보기 크기 필터에 걸려 탐지 해제
       → 프레이밍 대상에서 빠짐 → 줌인 → 다시 잡힘 → 반복
```

게다가 레지스트리 폴백이 "탐지 0명"일 때만 발동해서, **5명 중 1명만 잡히면 나머지 4명은 영영
프레이밍에서 빠졌다.** 자동 정찰은 연출이지 센서 시뮬레이션이 아니므로 레지스트리에서 실제
위치를 직접 읽게 했다(낙하산 관측 판정만 예외 — 그건 "카메라가 알아봤나"가 요점).

### 3.6 MoveDroneToPath가 경로 끝까지 주행

`uavpath2`는 "시작점=트럭, 끝점=낙하산"이라 **끝까지 날아가면 방금 떠나온 낙하산 자리로
되돌아간다.** 실측: 관측 중이던 630m에서 994m까지 24초간 역주행했고 그동안 1차 전투가 끝났다.
교전을 따라가는 경로는 "타고 갈 길"이 아니라 **"미끄러질 레일"** 이다 — 이미 관측 중이면
경로 주행 없이 레일만 갈아탄다.

### 3.7 시나리오 스텝을 월드 상태 대신 믿음

"3분대 제외 전멸 → 이동형지휘소만 프레이밍"의 조건은 **월드 상태**인데 시나리오 스텝 발동
타이밍에 맡겼다. 실측에서 2차 전투지에 적 8명이 살아 있는데 세트가 3으로 넘어와, 그 8명을
통째로 버리고 530m를 날아갔다. **상태로 게이트**하게 고쳤다 — 마지막 분대가 아닌 적이 살아
있으면 3차 전환을 보류하고 직전 세트를 유지한다.

### 3.8 UGV도 RCWS를 달고 있다

"트럭 RCWS가 교전을 시작했는가"를 프레이밍 액터의 `RCWSFireControlComponent`로 판정했는데,
세트와 무관하게 검사해서 **1차 전투지에서 UGV의 자동조준이 래치를 걸어버렸다**(세트=1 설정
0.1초 뒤에 "교전 개시 포착"이 찍힘). Zone3에서만 검사하도록 막았다.

## 4. 비행 유도 — 구조적 결함 3연쇄

관측 이동이 계속 "덜컹/울렁"거렸는데, 원인이 겹쳐 있어서 하나씩 벗겨내야 했다.

### 4.1 적분 와인드업 (안티와인드업 누락)

속도 적분기가 가속도 상한 포화를 모른 채 계속 쌓였다. 먼 지점으로 출발하면 P항만으로 이미
상한을 넘는데 그동안 적분이 0.5초 만에 상한(2.0m/s²)에 포화 → 목표 속도에 도달해 오차가
0이 돼도 계속 가속 → 초과 → 적분이 풀리며 과감속 → **±11.5° 기울기가 3~5초 주기로 진동.**

조건부 적분으로 고쳤다(적분을 반영했을 때 포화가 더 심해지면 그 갱신을 버림). 비행 컴포넌트의
각속도 PID는 원래 그렇게 돼 있었는데 오토파일럿에만 빠져 있었다.

### 4.2 그 안티와인드업을 축별로 안 함

1차 수정이 **수평 포화 하나로 3차원 적분 전체**를 수락/거부했다. 양방향으로 틀렸다 —
출발 가속으로 수평이 포화한 동안 수직 적분까지 얼어붙어 고도를 못 따라가고, 반대로 수직
상한 포화는 아무도 안 봐서 Z 적분만 그대로 와인드업했다. 수평(XY 벡터 크기)과 수직(Z 절대값)을
**각자의 상한으로 따로** 판정하게 고쳤다.

### 4.3 속도 피드포워드 부재 → 저감쇠 진동 (본체)

위 둘을 고쳐도 **속도가 사인파로 출렁였다.** 캐스케이드 특성방정식을 풀어보니:

```
s³ + Kv·s² + (Kv·Kp + Ki)·s + Ki·Kp = 0
Kp=0.7, Kv=1.4, Ki=0.5  →  ωn = 1.07 rad/s,  ζ = 0.51,  주기 6.8초
```

여기에 내부 루프 지연(지령평활 0.1s + 자세루프 0.125s + 모터 0.06s ≈ 0.29s)이 그 주파수에서
위상을 15° 더 깎아 **실효 ζ ≈ 0.4.** 관측 지점이 갱신될 때마다 이 모드가 재여기됐다.

원인은 경로 추종과의 **비대칭**이었다:

```cpp
if (bFlyThroughAtSpeed)   // 경로 추종 — 거버너 속도를 그대로 = 이미 피드포워드
    DesiredVelocity = ToCarrot.GetSafeNormal() * SpeedMS;
else                      // 관측 — 위치 오차만으로 속도를 짜냄
    DesiredVelocity = (TargetM - PosM) * PositionP;
```

경로 추종이 부드러웠던 이유가 이거였다. 관측에도 피드포워드를 넣고(유도점의 실제 진행 속도),
적분을 관측 모드에서만 0.15배로 줄이고(ζ 0.51 → 0.68), 유도점에 사다리꼴 속도 프로파일을
씌워 피드포워드 자체를 연속으로 만들었다.

### 4.4 포화가 히스테리시스를 무력화 (마지막 조각)

그래도 5초 주기로 턱턱거렸다. 로그를 보니 **필요 화각이 84~90°로 계속 최대치 근처**였다 —
`bAcceptableToStay` 조건이 `화각 ≤ 90°`인데 대상이 33~38개라 거의 항상 초과. 히스테리시스가
통째로 무력화되어 **매 평가마다 덜 나쁜 곳을 새로 골랐고**, 체류시간 5초가 그대로 계단 주기가
됐다. 한 계단(20~60m)이 곧 가속→감속 한 사이클.

사용자 가설("UGV가 멀리서 움직이니 프레임이 실시간으로 늘어난다")이 정확히 이 포화를 만드는
경로였다. 처방 둘:

- **도주 중인 적을 트래킹에서 제외**(`EEnemyState::Flee`) — 전장 밖으로 빠르게 멀어져 프레이밍을
  늘리는 주범. 연출상으로도 "도망친 놈은 놓아주고 다음 전투지에서 다시 잡는다"가 맞다.
- **차선 모드 개선 마진** — 포화 분기에 머물더라도 지금 자리보다 확실히 나을 때만 옮긴다.

## 5. 카메라와 기체 방향 분리

기수를 대상 쪽으로 계속 돌리고 있었다. 주석에 "짐벌 요 여유 확보"라고 써뒀는데 **그 전제가
틀렸다** — 짐벌 요는 클램프가 없고(`Fmod`만), 목표를 매 틱 기체 좌표계로 변환하므로 기수가
어디를 보든 카메라는 대상을 문다. 옆으로 수백 미터를 날며 피사체를 계속 향하면 방위각이
빠르게 쓸려 **기체가 빙글빙글 돌았다.**

사용자 지적("카메라 방향과 진행방향을 분리하면 되잖아, 뒤로 날아도 되고")대로 **기수를
래치하고 8°/s 상한 안에서만** 돌리게 했다. 급회전이 구조적으로 불가능하고, 기체가 천천히 도니
짐벌(슬루 25°/s)이 여유 있게 상쇄해 영상도 안정된다.

## 6. 곁가지로 잡은 탐지 버그

교전 중 적군 탐지 박스가 하나둘 사라지고 2차 전투지에선 전멸했다. 원인은 **폰의 미러
프로퍼티가 컴포넌트 설정을 매 플레이마다 덮어쓴 것**:

```
BP_Drone → TargetDetection 컴포넌트:  MinScreenSizeFraction = 0     ← 사용자가 끔
BP_Drone → 폰:                        DetectionMinScreenSizeFraction = 0.04
BeginPlay:  TargetDetection->MinScreenSizeFraction = DetectionMinScreenSizeFraction;  // 0 → 0.04
```

그리고 이 필터는 **거리가 아니라 화면 점유율** 기준이라 화각에 반비례한다. 1.8m 병사 기준:

| 짐벌 가로 화각 | 유효 탐지거리 |
|---|---|
| 30° (줌인) | 150 m |
| 79.5° (1차 광각) | 51 m |
| 88° (2차 광각) | 45 m |

`MaxDetectionRange` 800m가 통째로 가려졌다. 폰의 미러를 제거해 **컴포넌트 프로퍼티가 유일한
기준**이 되게 했다.

UGV/트럭도 같은 함정이 있는지 전수 검색했으나 **코드가 그 필드를 대입하는 곳은 드론뿐**이었다.
트럭은 `MinScreenSizePixels=12`를 의도적으로 켜뒀는데, 줌 0.5배(최대 광각)에서만 235m로
조여지고 1배 이상이면 `MaxDetectionRange`(400m)가 먼저 걸려 실질 영향이 없다 — 조준경의
물리적 성질에 가까워 그대로 뒀다.

## 7. 남은 것

- [ ] **도주 시작 장면이 화면에 잘 안 보인다.** 그 시점 프레이밍이 대상 33개·화각 84°라 도주하는
      적이 점으로 보인다. 시나리오 표 4단계("3분대 도망 시작 → UGV+적군 전체+아군 전체")를
      그대로 구현한 결과라, 보여주려면 그 단계만 대상을 좁히는 별도 결정이 필요하다.
- [ ] **경로 고도 부족** — 부감이 -30~-40°대에 머물러 선호 범위(-45~-60°)를 못 채운다.
      교전 반경 R에 대해 대상보다 **R × 1.0~1.25 위**가 기준.
- [ ] 2프로세스(2대 PC) 실환경 검증 — 이 시스템은 시뮬 권위 프로세스에서만 돈다.
