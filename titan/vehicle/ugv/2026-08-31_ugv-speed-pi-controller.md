# UGV 자율주행 속도 제어기 재작성 (P 배율 → PI)

선행 문서: `2026-08-22_ugv_corner_braking_dev_guide.md`(2026-08-22, 커브 선행 감속 도입),
`2026-08-26_ugv_obstacle_avoidance.md`(조향/커브 감속 튜닝)

---

## 1. 증상

사용자 관찰:
- 자율주행이 목표 속도에 한참 못 미친 채로 달림
- 기어가 5단으로 순항하다 장애물 회피로 감속 → **1~2단까지 다운시프트** → 다시 5단으로 올라가는
  변속 지연 때문에 재가속이 느림. 오르막이면 더 심함
- 오르막에서 속도가 죽음

처음엔 "오르막/내리막을 감지해서 가속/감속을 보정하는 로직"을 새로 넣는 방향으로 설계하다가,
사용자가 **"목표 속도와 현재 속도 차이를 실시간으로 보고 스로틀을 주면 되는 것 아닌가"** 라고
지적하면서 방향이 바뀌었다. 그게 맞았고, 기존 제어기에 구조적 결함이 있었다.

## 2. 원인 — 속도 제어가 "배율"이었다

```cpp
float Throttle = clamp(1 - |조향오차| / ThrottleCutoffAngleDeg, 0, 1);   // 조향컷
...
SpeedScale = clamp((목표 - 현재) / CornerSpeedRampBandKmh, -1, 1);
Throttle   = (SpeedScale >= 0) ? Throttle * SpeedScale : SpeedScale;      // ← 곱셈
```

속도 오차를 보긴 했지만 **P 하나뿐이었고, 그마저 스로틀에 곱하는 배율**이었다. 결과:

- 목표에 가까워질수록 스로틀이 0으로 빠진다 → **목표 속도를 유지할 수단이 아예 없다**
- 항력·경사와 균형이 맞는 지점에서 목표보다 한참 아래로 수렴한다
- 오르막은 필요한 스로틀이 더 큰데 제어기는 오히려 0으로 빼므로 **격차가 더 벌어진다**

### 로그 증거 (수정 전)

```
v=36.7  cornerTarget=47.4  angErr=-0deg  throttle=0.54   ← 10.7km/h 미달인데 스로틀 절반
v=36.3  cornerTarget=44.4  angErr= 2deg  throttle=0.40
v=31.2  cornerTarget=31.2  angErr= 0deg  throttle=-0.00  ← 목표 도달 순간 스로틀 0
```

조향 오차가 0도라 조향컷과 무관했다. 역산하면 `CornerSpeedRampBandKmh ≈ 20`
(10.7/0.54 ≈ 19.8, 8.1/0.40 ≈ 20.2) — **목표보다 20km/h 아래여야 스로틀이 1.0**인 매우 무른
제어기였다.

**기어 헌팅도 이것의 2차 증상이다.** 스로틀이 `0.54 → 0.03 → 0.74`로 출렁이니 RPM도 같이
출렁이고, 그게 다운시프트/업시프트를 유발한다.

## 3. 수정 — 절대 스로틀을 내는 PI 제어기

```cpp
오차   = 목표 - 현재
적분  += 오차 × dt              // anti-windup: 포화 방향이면 누적 정지
스로틀 = clamp(Kp×오차 + Ki×적분, -1, 1)
```

**적분항이 "그 속도를 유지하는 데 필요한 스로틀"을 알아서 쌓는다.** 그래서 설계하던
**경사 감지 로직이 통째로 불필요해졌다** — 오르막·내리막·항력·노면 저항이 전부 속도 오차 하나로
흡수된다. Pitch 측정도, 저역통과 필터도, 게인 튜닝도 없다.

### 조향컷을 스로틀이 아니라 "목표 속도"에 곱하도록 이동

이게 두 번째 핵심이다. 조향컷을 예전처럼 스로틀에 곱하면 **적분과 싸운다** — 커브에서 스로틀이
눌려 속도가 안 나고, 그동안 적분이 계속 쌓이다가 커브를 빠져나오는 순간 터진다.

목표 속도에 곱하면 **오차 자체가 줄어 적분이 애초에 안 쌓인다.** `SteeringSpeedFactorFloor`(0.35)로
목표가 0까지 내려가 급제동이 되는 것도 막았다.

### 적분 리셋 지점

- `MoveToDestination`(새 경로 시작) — 직전 경로의 오르막 보상분이 남아 출발 순간 스로틀이 미리
  들어가는 걸 막는다. `LastCornerTargetSpeedKmh`/`YawRateIntegral`과 같은 자리
- 거버너 비활성 구간(`bEnableCornerBraking`/`bEscortSpeedLimitActive` 둘 다 꺼짐) — 다시 켜지는
  순간 예전 값으로 튀는 걸 막는다

### 신규 프로퍼티 (`UGV AI | Chaos Pursuit`)

| 이름 | 기본값 | 역할 |
|---|---|---|
| `bUseSpeedPIController` | true | **끄면 예전 배율형 P로 즉시 복귀**(재빌드 불필요) |
| `SpeedThrottleKp` | 0.08 | 오차 12.5km/h에서 스로틀 가득 |
| `SpeedThrottleKi` | 0.05 | 오차 3km/h 지속 시 초당 0.15씩 축적 |
| `SpeedIntegralMaxThrottle` | 0.6 | 적분 기여분 상한(anti-windup) |
| `SteeringSpeedFactorFloor` | 0.35 | 조향컷의 목표 감쇠 바닥 |

`CornerSpeedRampBandKmh`는 이제 예전 경로에서만 쓰인다.

### 진단 로그 확장

```
[UGVPursuit] v=35.9km/h cornerTarget=39.2 spdTgt=38.6 spdI=0.53 pitch=4.2 | angErr=1deg ... throttle=0.74
```
- **`spdTgt`** — 조향컷까지 반영된 실제 추종 목표
- **`spdI`** — 적분이 만든 스로틀 기여분. **경사/항력 보상이 얼마나 걸려 있는지가 여기 보인다**
- **`pitch`** — 차체 피치(경사 검증용)

## 4. 실측 결과 — 제어기는 고쳐졌고, 병목이 옮겨갔다

### 잘 된 것

`spdI` 평균 **0.44** — 경사·항력을 이기기 위해 **스로틀의 44%를 적분이 공급**하고 있다. 예전
제어기에는 이 항이 아예 없었으니 그만큼이 통째로 빠져 있었던 것. 오르막 구간만 보면 더 높다:

| 구간 | 샘플 | 평균 `spdI` | 평균 throttle | 평균 미달 |
|---|---|---|---|---|
| 오르막 (pitch > 5°) | 302 | **0.51** | 0.80 | 10.7 km/h |
| 평지 (\|pitch\| < 2°) | 6 | 0.26 | 0.29 | 7.9 km/h |

**Pitch 감지 로직 없이 경사 보상이 자동으로 걸린다는 직접적인 증거다.**
목표 초과가 105회, 브레이크 28회 — 예전엔 목표를 넘는 일 자체가 드물었으니 이제 진짜로 목표를
쫓고 있다.

### 그런데 절반은 스로틀을 다 밟고도 못 따라간다

| 지표 | 값 |
|---|---|
| 평균 미달 (수정 전 → 후) | 11.97 → **9.96 km/h** |
| 목표 ±3km/h 이내 | 123/458 (**27%**) |
| **스로틀 포화(≥0.99)인데 3km/h 이상 미달** | **230/458 (50%)** |
| `spdI` 최대 | **0.60 = 상한에 붙음** |
| pitch 범위 | −9.6° ~ +14.9° |

**스로틀 1.0, 적분도 상한까지 차오른 상태에서 여전히 10km/h 부족하다.** 이건 더 이상 제어 문제가
아니라 **차가 그 속도를 낼 힘이 없는 것**이다.

### 그래서 병목이 바뀌었다

- **수정 전**: 제어기가 병목 — 스로틀을 0.5밖에 안 줬으니 토크를 올려도 소용없었다
- **수정 후**: 구동력이 병목 — `MaxTorque` / 기어비 / `DragCoefficient` 축으로 넘어갔다

기어 헌팅도 여기서 설명된다. 5단 순항 → 회피 감속 → 1~2단 다운시프트 → 오르막이라 복귀가 느림.
그동안 목표는 초당 20km/h(`CornerTargetReleaseRateKmhPerSec`)씩 회복되니 격차가 벌어진다.
미달 p90이 25.3km/h인 게 그 구간들이다.

## 5. 다음 단계 (미적용, 선택)

**A. 목표를 현실에 맞추기 (즉시·무료)**
`CornerStraightSpeedKmh`가 60인데 이 차는 이 지형에서 36km/h 근처가 한계다. **40~42로 낮추면**
추종률이 크게 올라가고 적분이 상한에 붙어 사는 상태도 해소된다. 실제 주행 속도는 지금과 거의
같다(어차피 못 내던 속도).

**B. 구동계 (근본)**
- `TransmissionSetup` — 기어 단수 축소(5단 → 2~3단) 또는 `GearChangeTime` 단축.
  궤도차량에 5단 이산 변속은 원래 부자연스럽다
- `EngineSetup → MaxTorque` / `TorqueCurve` 상향
- 저단에 오래 머무는 게 문제면 `ChangeUpRPM` 하향

**C. 그대로 두기** — "안 부딪히고 목적지 도착"이 목표면 지금도 충분하다.

## 6. 곁다리 관찰

조향이 이제 가끔 포화된다(`steer=±1.00`). `YawRateKp`를 0.12로 올린 뒤부터인데,
`2026-08-26_ugv_obstacle_avoidance.md` 4.3절에서 **0.08 대비 측정상 이득이 없었다**고 결론 낸
값이다. 조향이 흔들리면 0.08로 되돌리는 것을 우선 후보로 둘 것.
