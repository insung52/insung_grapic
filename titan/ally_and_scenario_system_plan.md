# 아군 BP + 시나리오 관리 시스템 — 설계 논의 (2026-07-28, 착수 전 정리)

> 아직 구현 시작 전. `all.md`(공식 시나리오 명세) + `memo.md`(사용자 개인 TODO) +
> 기존 dev guide들을 근거로 "아군에 뭐가 필요한가"를 먼저 정리하고, 구현은 이 문서에
> 합의된 뒤 별도로 진행한다.

## 1. `all.md` 시나리오에서 아군이 실제로 하는 일

Phase #4 (#4-1~#4-8) 타임라인에서 아군이 명시적으로 언급되는 지점만 추리면:

- **#4-1**: 아군 30명 초기 배치, 대기 상태(다른 모든 것도 정지 상태).
- **#4-6** (적군 이동 시작 시점에 트리거): "적 예상 침투로내 여단 정보중대 **2개 소대**
  매복명령" — 적군의 예상 이동 경로에 아군이 매복. **"나무 뒤 엄폐 및 수풀에 엎드려
  대기하는 애니메이션 적용"**이 유일한 구체적 지시사항.
- 그 외 구간(#4-7/#4-8): 실제 사격/교전은 UGV RCWS와 자체방호 RCWS가 담당. 아군이
  직접 사격하거나 이동한다는 서술은 **없음** (#4-7에 "적 병력 일부(5명)는 이동형
  지휘소 위치로 이동"이 있지만 이건 **적군**이 도주하는 묘사).

즉 **`all.md`만 놓고 보면 아군에게 요구되는 건 "①대기 → ②매복 위치로 이동(또는 이미
그 자리에 배치되어 있다가) → ③엄폐 자세 애니메이션 재생" 정도**로, 사용자가 처음
제안한 "UGV 전후방으로 무리지어 자동 주행"보다 범위가 좁다. `#4-5/#4-6/#4-7`에
"확인 필요사항: (미기재)"가 반복되는 걸 보면 이 부분 자체가 원래 설계에서도 디테일이
비어있는 구간 — 우리가 합리적으로 채워야 하는 부분.

## 2. `memo.md`(사용자 개인 TODO)에 있는 추가 단서

`all.md`보다 더 구체적인 의도가 몇 줄 적혀 있음:

- **"아군 bp 따로 만들기 (ugv 따라서 뒤에서 이동)"** — 사용자가 이미 예전에
  "UGV를 따라 뒤에서 이동"을 아이디어로 적어둔 적 있음. `all.md`의 "매복"과
  합치면: **평소엔 UGV를 따라 대열 이동 → 매복 트리거(#4-6) 시점에 그 자리에서
  엄폐 자세로 전환**하는 그림이 자연스럽게 맞아떨어짐 (사용자가 이번에 제안한
  것과 사실상 같은 결론).
- **"적군 bp 에서 에러 발생"** — 미해결로 남은 항목. 정확히 어떤 에러인지는
  기록이 없음 — BP_Enemy를 레벨에 배치하고 재현해보며 파악 필요.
- **"새로운 레벨 오면 할거 — 처음 아군들 위치(도로옆 텐트) (15 15 나눠서)"** —
  아군을 **2그룹(15+15)**으로 나눈다는 것도 `all.md`의 "2개 소대"와 일치. 초기
  대기 위치는 도로 옆 텐트로 예정.

## 3. 현재 구현 상태 감사 (문서 기준 — MCP 재연결 후 라이브 확인 필요)

### BP_Enemy (`Content/Tutorial/Blueprints/Enemy/BP_Enemy`)
`detection_dev_guide.md` 6절 기준:
- 낙하산 강하(`AS_Falling`/`AS_Falling_To_Landing`/`AM_Hard_Landing`) → 랜덤 지점
  배회(`AS_Enemy_Looking_Around`) → 피격 시 사망(`AM_Enemy_Death_Montage`/
  `AM_Enemy_Death2` 2종 + 래그돌 + 자동 삭제) 로직까지 **완비**.
- **능동적 전투 AI 없음** — 순수 배회+반응만. 대인화기 사거리에서 총 맞으면
  죽는 것 말고 아무것도 안 함(시나리오상 정확히 맞는 동작 — `memo.md` "보행
  ANIMATION 적용 및 피격 시 쓰러짐"과 일치).
- 데미지: 엔진 표준 파이프라인(`Event AnyDamage`)으로 이미 반응 — RCWS 발사체
  (`ARCWSProjectile`)가 `ApplyPointDamage`만 호출하면 그대로 작동
  (`rcws_fire_control_dev_guide.md` 7.2절).
- **사용자가 직접 했어야 하는 것(MCP로 그래프 편집 불가해서)**: `DetectableTargetComponent`
  (`Faction=Enemy`) 추가 + `Event AnyDamage`의 사망 분기에 `SetIncapacitated(true)`
  연결(`rcws_fire_control_dev_guide.md` 7.3절/10절). **이게 실제로 됐는지, 그리고
  `memo.md`의 "적군 bp 에러"가 이 작업 중 생긴 건 아닌지 — MCP 재연결 후 BP_Enemy를
  직접 열어서 확인 필요.**
- 레벨에 아직 미배치(사용자 확인).

### 아군

  (스켈레탈 메시 + 스켈레톤 + 피직스 애셋). **애니메이션은 확인된 게 이 정적

## 4. 제안 — 아군 BP 기능 목록

`all.md` + `memo.md` 종합, 우선순위 순:

1. **상태 머신 (최소 3단계)**: `Standby`(초기 대기, 텐트 옆) →
   `Following`(UGV 뒤 대형 유지 이동) → `Ambush`(엄폐 자세, 정지).
   `Following`→`Ambush` 전환은 좌표/타이머가 아니라 **시나리오 트리거**(아래 5절)로.
2. **대형 유지 이동**: UGV 위치를 기준으로 각 병사가 자기 슬롯(전방 N명/후방 N명,
   또는 좌우 2열 등 — 배치 패턴은 논의 필요)의 상대 오프셋을 목표로 `MoveTo`.
   UGV 속도에 맞춰 걷기/뛰기 애니메이션 블렌드 필요("아군 속도를 따라서 주행하는건
   없음"이라고 하신 부분 — UGV 쪽엔 이미 자동주행이 있으니, 아군 쪽에서 UGV와의
   거리를 보고 스스로 속도 맞추는 게 자연스러움. UGV가 아군 속도에 맞추는 것보다
   구현이 단순함).
3. **엄폐 위치**: 2절에서 나온 "매복 위치는 사전 배치냐 실시간 탐색이냐" 질문에
   대한 답 — **사전 배치(레벨에 미리 놓인 마커/웨이포인트 액터, 또는 시나리오
   데이터에 좌표로 기록)**. 사용자가 이미 이 방향으로 결론 내림("자동으로 장애물
   찾고 그러는거보단... 시나리오를 미리 기록해놓고"). 나무/수풀 위치를 코드가
   자동으로 판단하는 것보다, 레벨 디자이너(또는 우리)가 적당한 엄폐 지점을 직접
   찍어두는 게 훨씬 안전하고 예측 가능함.
4. **DetectableTargetComponent(Faction=Friendly)** — RCWS/UAV가 아군도 인식은
   하되(피아식별 목적), 사격 대상에서는 제외(이미 `SelectNearestEnemyTarget`이
   `Faction==Enemy`만 거르므로 코드 추가 없이 자동으로 안전).
5. **경량 액터** — 30명(+적군 15명)이 동시에 존재하므로, `BP_Enemy` 급의 무거운
   BP를 그대로 복붙하기보다 필요 기능만 남긴 가벼운 버전 권장
   (`detection_dev_guide.md`도 이미 "더 가벼운 액터로 별도 구현"이라고 계획해둠).
   구체적으로 뭘 빼도 되는지(래그돌 필요 여부, 사망 애니 필요 여부 — 아군이
   피격당하는 시나리오가 있는지 `all.md`엔 없음)는 확인 필요.
6. **(낮은 우선순위, all.md에 명시 없음)** 아군이 직접 사격하는 기능 — 지금
   시나리오상 교전은 전부 RCWS가 담당하므로 당장은 불필요. 나중에 요구되면 추가.

## 5. 제안 — 시나리오 관리 시스템

사용자 아이디어(JSON/텍스트로 시나리오를 미리 기록해두고 재생 시 따라가는 방식)에
동의 — 이 프로젝트 자체가 처음부터 "LLM/UDP로 외부 신호를 받아 정해진 단계를 순서대로
진행"하는 구조(`all.md` #4-1~#4-8 자체가 이미 그런 스펙)라 잘 맞음. 이미 있는
`UScenarioStateSubsystem`을 처음부터 새로 만들지 말고 **거기에 단계 개념을 얹어
확장**하는 걸 제안:

- **스텝 정의**: 이름(예: `"4-6_Ambush"`), 시작 조건(타입: 수동 트리거 / 좌표
  근접 / 타이머 / 이전 스텝 완료 등), 효과(스폰/이동/애니메이션 트리거/UI 메시지/
  미니맵 마커 등) — `all.md`의 각 `#4-N` 섹션이 이미 이 구조 그대로임.
- **데이터 소스**: 처음엔 `UDataTable`/`UDataAsset`(C++에서 구조체만 정의하면
  에디터에서 표 형태로 채울 수 있어 코드 재컴파일 없이 튜닝 가능 — MCP의
  `DataTableTools`로도 다룰 수 있음) 권장. 순수 JSON 파일 파싱은 나중에 외부
  LLM/UDP 신호와 실제로 연동할 때(현재 `all.md` "확인 필요사항"으로 남아있는
  통신 프로토콜이 정해지면) 다시 고려.
- **트리거 검사**: 지금 `RCWSFireControlComponent`/`UGVAIController`에 이미
  있는 "거리 체크 + 브로드페이즈" 패턴 재사용 가능(이번 세션에 도로 이탈 감지에서
  썼던 것과 같은 부류).
- **아군 상태 전환도 이 시스템의 소비자**로 — 아군 BP가 직접 "내가 지금 몇 초째냐"를
  들고 있는 게 아니라, 시나리오 매니저가 "지금 Ambush 단계다"를 브로드캐스트하면
  모든 아군 인스턴스가 그걸 구독해서 전환. UGV/UAV도 앞으로 #4-2/#4-4 같은
  좌표 수신 단계를 붙이려면 결국 이 시스템을 거쳐야 함 — 아군만을 위한 시스템이
  아니라 전체 시나리오 자동화의 첫 조각으로 보는 게 맞음.
