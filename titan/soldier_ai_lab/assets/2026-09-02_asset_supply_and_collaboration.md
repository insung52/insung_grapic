### 2.3 Mixamo 리그 vs UE5 Manny — 실제 차이

리깅 재작업이 "이름만 바꾸는 일"이 아닌 이유:

| | Mixamo (현재) | UE5 Manny |
|---|---|---|
| 스파인 | Spine / Spine1 / Spine2 (**3개**) | spine_01 ~ spine_05 (**5개**) |
| 트위스트 본 | **없음** | upperarm / lowerarm / thigh / calf twist |
| Root | **없음** | 있음 (지면 높이) |
| IK 본 | **없음** | ik_foot_root, ik_foot_l/r, ik_hand_root, **ik_hand_gun** |

- 스파인 개수와 트위스트 본이 다르므로 **스킨 웨이팅은 실질적으로 새로 해야 한다.** 지금
  진행 중인 웨이팅 작업이 나중에 상당 부분 재작업이 된다는 뜻이다(9절에서 다룸).
- 반대로 이것이 리그 교체의 이득이기도 하다 — 트위스트 본이 있어야 팔뚝 비틀림에서 메시가
  안 무너지고, `ik_hand_gun`이 있어야 무기 부착/손 IK가 엔진 표준 규약을 쓴다.

## 4. 핵심 발견 — `EncodeRootBoneModifier`로 루트모션을 합성한다

### 4.1 엔진에 내장된 도구다

UE5.8의 `AnimationModifierLibrary` 플러그인(정식 등급)에 다음 애니메이션 모디파이어들이
들어 있다. 엔진 소스에서 직접 확인했다:

```
UEncodeRootBoneModifier      ← 핵심. 가중치를 준 본들로부터 루트 본의 위치/회전을 계산해서 인코딩
UCopyBonesModifier           ← 본 트랜스폼 복사 (SourceBone → TargetBone, 지정 공간에서)
UZeroOutRootBoneModifier     ← 루트 본 초기화
UReOrientRootBoneModifier    ← 루트 본 방향 재설정
UMotionExtractorModifier     ← 본 모션에서 커브 추출
UMirrorModifier / UFootstepAnimEventsModifier / UCurveFromSyncMarkersModifier
```

`UEncodeRootBoneModifier`의 실제 인터페이스:

```cpp
UCLASS()
class UEncodeRootBoneModifier : public UAnimationModifier
{
    // 루트 "위치"를 계산할 때 참고할 본들 + 각각의 가중치
    TArray<FEncodeRootBoneWeightedBone>      WeightedBoneToComputeRootPosition;
    // 루트 "회전"을 계산할 때 참고할 본들 + 가중치 + 어느 축을 쓸지
    TArray<FEncodeRootBoneWeightedBoneAxis>  WeightedBoneToComputeRootOrientation;
};
```

즉 **"발 두 개와 골반을 가중 평균해서 루트를 만들어라"** 같은 지시를 줄 수 있다. 이게 정확히
인플레이스 클립을 루트모션 클립으로 바꾸는 작업이다.

### 4.2 파이프라인

```
[1] 무료 인플레이스 클립 확보          (Mixamo / ASP / Lyra 등)
      ↓
[2] IK Retargeter 로 UE5 Manny 스켈레톤으로 리타깃
      → 타깃 스켈레톤에 root 본이 있으므로 root가 생기지만, 아직 원점에 고정
      ↓
[3] UEncodeRootBoneModifier 적용
      → 발/골반 가중 평균으로 root의 위치·회전을 계산해서 인코딩
      ↓
[4] UMotionExtractorModifier 적용  →  contact_l / contact_r 접지 커브 생성   ★ 필수
      BoneName=foot_l/foot_r, MotionType=TranslationSpeed, bNormalize=true,
      bUseCustomCurveName=true
      ↓
[4b] Enable_Warping 커브 생성                                              ★ 필수
      "동작이 직선인 구간 = 1". 없으면 Orientation Warping이 영원히 안 켜지고
      방향 커버가 전혀 안 된다. 루트 본 RotationSpeed를 뽑아 임계값 이하를 1로
      만드는 방식이 유력(P0-4에서 검증)
      ↓
[5] UFootstepAnimEventsModifier (선택)  →  발소리 싱크마커/노티파이
      ↓
[6] 시퀀스의 Root Motion 속성 활성화 (Enable Root Motion)
      ↓
[7] Pose Search Database에 편입 → Motion Matching 사용 가능
```

> **★ [4]단계는 2026-09-02 ABP 분석에서 추가된 필수 단계다.** GASP의 발 배치(`FootPlacement`
> 노드)는 애니메이션의 `contact_l`/`contact_r` 커브를 `RemapCurves`로 변환해서 "발 심기"
> 타이밍을 결정한다. **이 커브가 없는 클립은 발 IK가 오작동한다.** 외부 클립에는 이 커브가
> 없으므로 반드시 생성해야 한다. 상세: `../animation/2026-09-02_gasp_abp_analysis.md` 3.3b절.

- **애니메이션 모디파이어는 여러 시퀀스에 일괄 적용된다.** 수십 개를 한 번에 처리할 수 있다.
- **[2]와 [3]이 정확히 디자인팀이 할 수 있는 종류의 작업이다**(제작이 아니라 변환·정리).
  F1 제약과 충돌하지 않는다.

### 4.3 정직한 한계

이 파이프라인이 만능은 아니다. 넘어가면 안 되는 지점들:

| 한계 | 내용 | 완화 |
|---|---|---|
| **합성된 루트모션은 파생물이다** | 원본에 없던 정보를 발/골반에서 역산하는 것이라, 저작된 루트모션만큼 정확하지 않다 | 발 접지 구간이 명확한 클립일수록 잘 나온다. 클립별 검수 필요 |
| **Mixamo → Manny 리타깃의 골반 문제** | 리타깃된 루트모션 애니메이션에서 골반/힙 배치가 부정확해지는 것은 커뮤니티에 널리 보고된 현상 | IK Retargeter의 pelvis 체인을 별도 설정. 5.8의 foot plane/toe 정의와 Retarget Override Set 활용 |
| **프로포션 차이** | Mixamo 캐릭터와 Manny의 골격 비율이 다르다 | 리타깃 포즈 정합 + Stride/Orientation Warping이 상당 부분 흡수 |
| **커버리지는 그대로다** | 루트모션을 합성해도 **없는 동작이 생기지는 않는다.** Mixamo에 라이플 견착 start/stop/pivot이 없으면 여전히 없다 | **5절에서 별도로 다룬다 — 이게 진짜 남은 구멍** |

## 5. 남은 진짜 구멍 — 견착 자세의 전환 동작

4절로 "루트모션 없음" 문제는 풀리지만, **"동작 자체가 없는" 문제는 안 풀린다.**

| 필요한 것 | 상태 |
|---|---|
| 비무장 로코모션 + start/stop/pivot/turn | ✅ GASP가 완전히 커버 |
| 라이플 견착 정상상태 루프 (idle/walk/run) | ⚠ Mixamo/Lyra/ASP에서 조달 가능 |
| **라이플 견착 start / stop / pivot** | ❌ **무료 소스에 사실상 없음** |
| **라이플 견착 turn-in-place** (5.5.6절 재정렬용) | ❌ **무료 소스에 사실상 없음** |
| 엄폐 진입/이탈, 낮은 엄폐물 사격 | ❌ 무료 소스에 거의 없음 |
| 수신호 | ⚠ Mixamo에 유사 동작 일부 존재 |

### 완화 방안 3안 (P0-2 결과에 따라 선택)

**A안 — 견착 로코모션의 요구 수준을 낮춘다 (권장)**
조준 이동은 실제로 **느리고 전환이 적다.** 뛰다가 급정지하거나 180° 피벗하는 상황이 비무장
이동보다 훨씬 드물다. 따라서 견착 DB는 **커버리지가 낮아도 체감 손실이 작다.**
- 비무장/총내림 이동 = GASP 풀 품질 (전환 데이터 완비)
- 견착 이동 = 축소 DB + Orientation/Stride Warping으로 메움
- **전환이 필요한 순간(급선회 등)에는 자세를 총내림으로 바꾸는 것이 오히려 자연스럽다** —
  실제 병사도 급하게 움직일 때 총을 내린다. 즉 이 한계를 **연출로 흡수할 수 있다.**

**B안 — GASP 전환 동작을 견착 자세로 변환**
GASP의 start/stop/pivot(비무장)을 리타깃한 뒤, 상체만 견착 포즈로 교체해서 새 클립으로 굽는다.
`UCopyBonesModifier`로 상체 본을 견착 idle에서 복사하는 식.
- ⚠ **주의**: 이것은 런타임 레이어 블렌드가 아니라 **오프라인 클립 생성**이다. 아키텍처 문서
  5.5.1절이 금지한 것은 "런타임에 상하체를 따로 블렌드하는 것"이고, 오프라인으로 구워서
  하나의 풀바디 클립으로 만드는 것은 다른 이야기다. 다만 **품질은 검수해봐야 안다** —
  발맞춤과 상체 포즈가 안 맞으면 똑같이 어색해진다.
- 실험 가치는 있다. P1에서 시도.

**C안 — 이 부분만 예외적으로 유료 구매를 제안**
A·B가 다 실패하면, "이 5~10개 클립만"이라는 최소 범위로 재협의. F2를 뒤집는 것이 아니라
범위를 좁혀 다시 판단받는 것.

## 6. 조달 전략 v2 — 커버리지 매트릭스

| 카테고리 | 공급원 | 필요 작업 | 담당 |

| 비무장 로코모션 전체 | **GASP** | 없음 (스켈레톤 일치) | — |
| 트래버설(볼팅/맨틀) | **GASP** | 없음 | — |
| 라이플 견착 루프 | Lyra → 부족분 Mixamo | 리타깃 + 루트모션 인코딩 | 디자인팀 |

| 피격 리액션 / 사망 | Mixamo (다수 존재) | 리타깃 (루트모션 불필요) | 디자인팀 |
| 수신호 | Mixamo 유사 동작 | 리타깃 + 수정 | 디자인팀 |

**디자인팀의 역할이 명확해진다: "제작"이 아니라 "리깅 + 리타깃 + 루트모션 인코딩 + 정리".**
F1 제약과 정확히 맞는 역할이다.

### 확인해둘 것
- Mixamo 라이선스: 이미 현행 프로젝트가 Mixamo 캐릭터/애니메이션을 쓰고 있으므로 선례가
  있으나, 납품물 기준으로 한 번 확인해두는 게 안전하다.

## 7. 협업 전략 — 지금은 공유하지 않는다

### 7.1 결정

**P0 검증(1주 타임박스)을 혼자 끝낸 뒤, 비교 영상을 들고 공유한다.**

### 7.2 근거

| 이유 | 설명 |
|---|---|
| **이미 한 번 보류된 제안이다** | 리그 교체 제안이 "다른 것 먼저"로 미뤄진 상태다. 같은 제안을 근거 없이 다시 올리는 것은 설득력이 떨어진다 |
| **없는 것은 근거가 아니라 시연이다** | 근거는 이미 확보돼 있다 — ① 현재 스켈레톤에 Root 본이 없음(에셋 덤프로 확인) ② Motion Matching은 루트모션이 필수(Epic 공식 문서). **"현재 스켈레톤으로는 UE5 최신 애니메이션 기능을 쓸 수 없다"는 의견이 아니라 사실이다.** 부족한 것은 이것이 실제로 얼마나 나아지는지 보여주는 것뿐 |
| **요청 규모가 아직 미정이다** | P0-2(견착 워핑 품질) 결과에 따라 필요 클립이 2방향인지 8방향인지 4배 차이가 난다. 이걸 모르는 채로 요청하면 필요 없는 작업을 시키거나 나중에 추가 요청을 하게 된다 |
| **검증은 우회로가 아니다** | P0-1·P0-2는 어차피 구현 1단계다. 따로 시간을 쓰는 게 아니라 그냥 1단계를 하는 것이고, 설득 자료는 그 부산물이다 |

### 7.3 만들어서 보여줄 것 — 나란히 비교 영상

```
같은 이동 시나리오, 화면 분할
  왼쪽 : 현재 titan_example 병사   (블렌드스페이스 + Mixamo 리그)
  오른쪽: SoldierLab 병사          (Motion Matching + Manny 리그)

보여줄 항목: 출발/정지 정확도 · 급선회 · 경사 · 발 미끄러짐 · 조준하며 이동
```

- **GASP 기본 캐릭터로 찍는다.** 우리 병사 메시가 필요 없다 — 오히려 *"엔진 기본 캐릭터인데도
  이 차이"* 가 더 강한 논거다.
- 디자인팀 공수 0, 에셋 구매 0으로 만들 수 있는 자료다.

## 8. 시간 리스크에 대한 답 — 대부분은 어차피 살아남는다

혼자 진행하는 것의 리스크는 "이 시간이 통째로 날아갈 수 있다"는 것인데, 실제로는 그렇지 않다.

**설계 문서 7~12절(인지 · 판단 · 분대 · 엄폐 · 명령 · 성능)은 스켈레톤과 완전히 무관하다.**
유틸리티 판단, 분대 blackboard, 사기, EQS 엄폐 선정, SmartObject 예약, 명령 스키마는 현재
Mixamo 리그 위에서도 그대로 동작한다.

| 리그 교체가 무산될 경우 | 비중 |
|---|---|
| ❌ 날아가는 것: 5·6절 (Motion Matching, 워핑, 조준 IK) | 약 25% |
| ✅ 살아남는 것: 7~12절 AI 시스템 전부 | 약 75% |

**그래서 작업 순서를 이렇게 잡는다:**

```
1단계 (짧게, 데모 목적)   P0-1 · P0-2   →  애니메이션 검증 + 비교 영상
2단계 (길게, 본체)        AI 시스템      →  리그 결정과 무관하게 100% 생존
```

애니메이션 쪽을 먼저 짧게 치고 나오면, 그 뒤 작업은 리스크가 거의 없다.

## 9. 지금 디자인팀이 하고 있는 작업에 대하여

현재 디자인팀은 **기존 22종 시퀀스 정리**와 **기존 스켈레톤의 스킨 웨이팅 수정**을 진행 중이다.

### 9.1 낭비가 아니다

`titan_example`은 납품이 걸린 현재진행형 프로젝트이고, **그 병사들은 지금 괜찮아 보여야 한다.**
스킨 웨이팅 개선은 현재 빌드의 품질을 직접 올리는 작업이다. SoldierLab 교체는 잘 되어도
나중 일이고, 안 될 수도 있다. **"다른 것 먼저"라는 판단은 합리적이었다.**

### 9.2 다만 나중에 정직하게 말해야 할 비용

2.3절에서 본 대로 Mixamo와 Manny는 스파인 개수와 트위스트 본이 달라서, **리그를 바꾸면
스킨 웨이팅은 실질적으로 새로 해야 한다.** 나중에 제안할 때 이 비용을 숨기지 말고 같이
제시할 것. 대신 얻는 것(트위스트 본에 의한 변형 품질, `ik_hand_gun` 표준, MM 사용 가능)을
함께 놓고 판단받는다.

### 9.3 기존 22종에 대해

F3에서 확인했듯 이것들은 Mixamo 다운로드다. 따라서:
- **폐기 비용이 거의 없다.** 제작물이 아니다
- 다만 4절 파이프라인을 쓰면 **일부는 살릴 수도 있다** — 리타깃 + 루트모션 인코딩을 거치면
  견착 루프 클립으로 재활용 가능하다. P1에서 판단
- `../../ally_animation_request.md`에 적힌 **"로코모션 중 상반신만 레이어 블렌드하면 상체가 붕
  뜬다"는 지적은 지금도 유효하고, 새 설계(아키텍처 문서 5.5.1절)의 핵심 근거로 인용되고 있다.**
  판단이 틀려서 다시 하는 게 아니라, 엔진 쪽 전제가 바뀌어서 다시 하는 것이다 — 나중에 이
  점을 분명히 전달할 것

## 10. 검증 항목 갱신 (V1~V6)

F1·F2 반영으로 우선순위가 바뀌었다.

| # | 항목 | 왜 | 우선순위 변화 |

| **V1** | **P0-1 — AI가 Motion Matching을 구동하는가** | 실패하면 루트모션 자체가 불필요해지고 계획 전체가 바뀐다 | 그대로 **1순위** |

| **V4** | 무기 그립 규약 (`ik_hand_gun` 기준) | 손 IK 요청과 무기 메시가 동시에 걸림 | 유지 |

## 11. 타임박스와 중단 기준

혼자 진행하는 방식의 유일한 실패 모드는 **"보여줄 게 안 나오는데 계속 붙잡고 있는 것"** 이다.

| 게이트 | 기한 | 실패 시 |
|---|---|---|
| P0-0 셋업 + PIE 확인 | 1일 | GASP가 5.8에서 안 돌면 즉시 중단·보고 |
| **P0-1 — AI가 MM 구동** | **3일** | 아키텍처 문서 5.3절의 대안 4개를 다 써도 안 되면 **중단하고 현행 유지** |
| **P0-2 — 견착 워핑 품질** | **2일** | 8방향이 필요하다고 나오면 5절 A/B/C안 재검토, 그래도 안 되면 계획 자체 재검토 |
| V6 — 루트모션 인코딩 | 1일 | 실패 시 Mixamo 소스를 포기 → 조달 가능 범위가 Lyra/GASP로 축소 |

**총 1주 안쪽.** 여기서 안 되면 접고, 되면 그 뒤는 리그 결정과 무관한 안전 구간(8절)이다.
