`260806_시스템 구성도.pdf`/`문의내용0806.md` 답변 + LIG 참조구현(`udp_test`,

## 1. 좌표계

**좌표계가 위경도(WGS84)가 아니라 UTM(Easting/Northing/Zone/Letter) 방식이 맞는지**
궁금합니다. 보내주신 참조구현(`udp_test`)의 `UGV_Period_NavigationInformation`,
`S_DetectedObject` 등에서 `East`/`North`/`Zone`/`Letter` 필드가 일관되게 나와서 UTM으로
추정했는데, 맞다면 단위(m 등), UTM Zone 번호, Datum(WGS84 기준인지) 정보도 부탁드립니다.

## 2. 프로토콜 세부

**2-1.** cmd 코드 전체 목록/데이터 송수신 참조 모듈 최신 진행 상황이 궁금합니다.

**2-2.** 요청↔응답, 이벤트↔ACK 상관관계 관련해서 — 메시지 봉투(`{cmd,src,recv,data}`)에
순번/요청ID가 없어서, 저희는 "같은 cmd는 이전 응답을 받은 뒤에만 다음 요청을 보낸다(서로
다른 cmd끼리는 동시 요청 가능)"는 방식으로 구현하려고 합니다. 혹시 원격통제기 쪽이 이와
다른 방식(예: 완전 순차 처리만 지원, 또는 진짜 동시 다발 요청 지원)을 전제로 하고 있다면
알려주시면 감사하겠습니다.

**2-3.** 메시지 봉투의 `src`/`recv` 필드에 실제로 device 코드(RC=20, UGV=14, UGV_RCWS=13,
UGV_ADU=12)가 들어가는 게 맞는지 궁금합니다. 참조구현에서는 이 필드들이 전부 리터럴 문자열
`"device"`로만 채워져 있어서 실제 사용 여부를 확인하고 싶습니다.

**2-4.** 참조구현에 배치된 통신 컴포넌트의 설정값이 IP `192.168.0.84`, 포트 `7777`/`7778`
(단일 포트쌍)으로 되어 있는데, 이게 개발 테스트용 임시값인지, 아니면 저희가 안내받은
실배포 스킴(UGV `192.168.10.10:8000`(주기)/`8001`(비주기))과 어떻게 다른지 확인
부탁드립니다.

## 3. 인프라

**3-1.** 자체방호(이동형지휘소) 통제기 SW의 고정 IP를 알 수 있을까요 — 이동형지휘소 SW가
상위체계로 RTSP 영상(CCTV/RCWS)을 직접 송출하는 RTSP 서버 역할이라(시스템 구성도상
확정), 상위체계가 영상을 당겨갈 주소가 필요합니다. (에뮬레이터-콘솔 간 RTSP는 이동형지휘소가
단일 프로그램으로 통합되면서 저희 쪽에서 이미 불필요해졌습니다 — 상위체계행 링크만
남았습니다.)

**3-2.** 저희 쪽에서 RTSP URL 경로/포트 규칙을 정해서 안내드릴 예정인데, 원격통제기/
상위체계가 임의의 RTSP URL에 접속 가능한 구조가 맞는지만 확인 부탁드립니다.

## 우리가 자체 결정한 것 (LIG 문의 불필요, 참고용)

- **UGV/자체방호축 배틀필드 공유**: 당연히 공유(리플리케이션) — 시스템 구성도에 링크가
  안 보였지만 우리 쪽 계획 그대로 유지.
- **RC→UGV 제어 명령(RC_RemoteDriving 등) 구현 주체**: 참조구현에 없어도 우리가 ICD 기준으로
  직접 구현.
- **재시도 횟수/타임아웃 값**: 임의로 정하고 설정 가능하게 노출(`udp_protocol_client`의
  `RetryConfig`처럼) — LIG 확정값 안 기다림.
- **`UGV_Response_Connection`/`BIT`/`BIT_ADU`의 정확한 의미**: 추측해서 구현, 아직 우리
  기능 자체가 없어서 지금 단계에선 확정 불필요.
- **Bounding Box 좌표 기준(카메라별 구분 등)**: `UGV_Period_ObjectDetectionResult`는 우리가
  생성하는 데이터라 우리가 설계 — 카메라별로 명확히 구분되게만 하면 됨, LIG 확인 대상 아님.
