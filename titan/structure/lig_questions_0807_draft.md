## 1. 프로토콜 세부 (남은 것)

**1-1.** 요청↔응답, 이벤트↔ACK 상관관계 관련해서 — 메시지 봉투(`{cmd,src,recv,data}`)에
순번/요청ID가 없어서, 저희는 "같은 cmd는 이전 응답을 받은 뒤에만 다음 요청을 보낸다(서로
다른 cmd끼리는 동시 요청 가능)"는 방식으로 구현하려고 합니다. 혹시 원격통제기 쪽이 이와
다른 방식(예: 완전 순차 처리만 지원, 또는 진짜 동시 다발 요청 지원)을 전제로 하고 있다면
알려주시면 감사하겠습니다.
- 이거 뭔소리임?

**1-2.** UTM 좌표 필드(East/North/Zone/Letter)의 정확한 Zone 번호와 Datum을 알 수 있을까요
— 시연 장소가 고정 지역이라 저희 쪽에서 경도 기반으로 자동 계산할 순 있지만, 실제 사용
중인 값과 맞는지 확인하고 싶습니다.
- 레벨디자인 끝나면 우리가 직접 위도경도값 기반으로 실제 위치 1:1 매핑 가능함. 질문 필요없음

**1-3.** 참조구현(`udp_test`)에 배치된 통신 컴포넌트의 설정값이 IP `192.168.0.84`, 포트
`7777`/`7778`(단일 포트쌍)으로 되어 있는데, 이게 개발 테스트용 임시값인지, 정식 ICD의
실배포 스킴(UGV `192.168.10.10:8000`(주기)/`8001`(비주기))과는 별개인지 확인 부탁드립니다.
- ip도 실배포 스킴 기본값에 초기화면에서 각각 커스텀 가능하게 개발할 예정. 질문 필요없음

## 이번에 정식 ICD로 해소된 것 (더 이상 질문 아님)

- **좌표계**: UTM(East/North/Zone/Letter) 확정, WGS84 아님.
- **cmd 코드 전체 목록/data 필드**: `lig_icd_ugv_rc_full.md`로 확정 — RC→UGV 방향(그동안
  비어있던 부분, `RC_RemoteDriving`/`RC_FireWeapon`/`RC_OperationMode` 등) 포함.
- **device 코드(RC=20/UGV=14/UGV_RCWS=13/UGV_ADU=12) 실사용 여부**: ICD 원문에 명시, 확정.
- **Bounding Box 좌표 형식**: 0~65535 정수 스케일링(좌상단/우하단), 계산식까지 ICD에 명시.

## 우리가 자체 결정한 것 (LIG 문의 불필요, 참고용)

- **UGV/자체방호축 배틀필드 공유**: 당연히 공유(리플리케이션) — 시스템 구성도에 링크가
  안 보였지만 우리 쪽 계획 그대로 유지.
- **재시도 횟수/타임아웃 값**: 임의로 정하고 설정 가능하게 노출(`udp_protocol_client`의
  `RetryConfig`처럼) — LIG 확정값 안 기다림.
- **`RC_OperationMode`(STAY/REMOTE/EMERGENCY) ↔ 우리 `EUGVDriveMode` 매핑**: 우리 내부
  설계 문제, LIG 확인 불필요 — Track4/5에서 재정의.
