# titan (문서 폴더) — 세션 공통 규칙

이 폴더는 `titan_example`(UE5.8, Perforce) 프로젝트의 개발 문서 저장소. 여러 Claude 세션이
독립적으로 작업하고 각자 문서를 남기는 방식이라, 문서가 뒤섞이기 쉬움 — 아래 규칙은 **여기에
새 문서를 만드는 모든 세션이 공통으로 지킬 것**(2026-08-31 도입, `titan_example/CLAUDE.md`와
동일한 규칙).

## 문서 작성 규칙 (필수)

1. **파일명에 날짜를 앞에 붙일 것**: `YYYY-MM-DD_짧은-주제.md`.
2. **문서 맨 위에 1줄 헤더**: `날짜 / 상태(완료·진행중·보류·설계단계) / 한줄요약`.
3. **폴더는 "시스템 하나당 폴더 하나" 축으로 고른다**(2026-08-31 재편 완료) — 아래 목록에서
   맞는 폴더에 그대로 두면 됨, 없으면 신설. 스테이징 폴더 없음. 주기적 "문서 정리" 세션이
   전체를 재스캔해서 `DOCS_INDEX.md`/`CURRENT_STATE.md`에 반영.

## 이 폴더의 최상위 문서

- `README.md` — 프로젝트 개요/시작점.
- `DOCS_INDEX.md` — 전체 문서 목록(날짜순/주제별), 정리 세션이 관리.
- `CURRENT_STATE.md` — 현재 프로젝트 상태 스냅샷, 정리 세션이 관리.
- `WORKLOG.md` — 전체 작업을 시간순으로 서술한 히스토리, 정리 세션이 관리.
- `guide/` — "이 시스템이 지금 어떻게 동작하는가"를 다루는 레퍼런스 문서 모음(에버그린,
  최신 유지 대상). 위 devlog 폴더들은 반대로 "무엇을 언제 조사·수정했는가"를 남기는
  기록 — 시간이 지나도 안 고침.
- `_archive/` — 더 이상 최신이 아닌 문서 보관(삭제 아님).
- `documents/` — LIG 원본 자료(PDF/PPTX/xlsx), Q&A 원문.

## guide/ 갱신 규칙 (2026-08-31 도입, 중요)

**작업으로 어떤 시스템의 실제 동작 방식이 바뀌었다면(예: RCWS 조작 방식 변경, UGV 주행
로직 재작성 등), 그 devlog만 남기지 말고 `guide/`에 해당 시스템의 레퍼런스 문서가 있는지
확인하고 있으면 같이 갱신할 것(없으면 새로 만들 필요는 없음 — 나중에 별도 정리 세션이
처리).** 이유: devlog는 쌓이지만 아무도 "지금 이 시스템이 정확히 어떻게 동작하는가"를 최신
상태로 유지하지 않으면, 나중에 `guide/` 전체가 옛날 정보가 되어버림(2026-08-31 문서 정리
때 발견된 문제 — `guide/`의 기존 문서들이 전부 이 상태였음, 각 문서 상단 경고 배너 참고).
