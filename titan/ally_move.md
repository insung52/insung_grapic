# 아군(BP_Ally_kadex) 이동/애니메이션 설계

## 0. 기본 모델

**Posture(자세상태)가 최상위 상태**이고, 그 안에서 **Movement(이동상태) × Alert(경계상태)** 조합이 실제 재생할 애니메이션을 고른다. 엄폐는 Posture와 같은 레벨에서 분기하는 별도 모드(4번 참고).

```
Posture(일반 / 숙이기 / 엎드리기)   ─ 최상위 FSM
  └ Alert(총 내림(미경계) / 경계·조준)  ─ Posture별 하위 상태
      └ Movement(정지 / 보행 / 달리기)  ─ 필요 시 방향까지 포함한 블렌드스페이스
```
엄폐는 이 트리 밖에서 Posture와 나란히 분기하는 별도 모드.

처음엔 "하반신=이동, 상반신=경계(에임오프셋)를 레이어로 합성"하는 구조를 생각했는데 **폐기**. 총을 들고 뛰는 것과 내리고 뛰는 것은 하반신뿐 아니라 상체 무게중심·토르소 앙게이지먼트·팔 스윙까지 전신이 달라져서, 레이어로 합성하면 상/하체가 따로 노는 이음새가 눈에 띔. 애셋 수 제약이 없으니 **Movement × Alert 조합마다 전신(풀바디) 애니메이션을 따로 쓴다** ("달리기+조준"과 "달리기+총내림"은 완전히 다른 풀바디 클립).

레이어/애디티브로 남겨도 되는 건 "전신 자세를 바꾸지 않는, 순간적으로 얹히는 동작"만: 재장전, 무기 살펴보기, 피격 리액션, 미경계 둘러보기 고개짓, 사격 반동, 그리고 조준 상태에서의 미세 Pitch 보정(AimOffset). 이런 것들은 지속적인 로코모션이 아니라서 레이어링해도 이음새가 거의 안 보임 — 이게 레이어링 써도 되는 것과 안 되는 것의 기준. **이 기준은 "정지 상태(Idle)"에도 그대로 적용됨** — 걷기/뛰기처럼 발맞춤에 동기화될 필요가 없는 정지 자세는, 하반신 Idle 베이스 위에 상반신 파지자세(무기 들었는지 여부는 사실상 전체 교체)+둘러보기 등을 레이어로 조합해도 됨. 안 되는 건 어디까지나 "로코모션 + 다른 파지자세"의 조합(10절 참고).

## 1. 이동상태

- 정지
- 보행
- 달리기
- 숙인 채 뛰기 (자세상태=숙이기 + 이동상태=달리기 조합. 낮은 자세 유지한 채로도 전력이동 가능해야 함)

기존처럼 Speed 스칼라 하나로 Idle↔Run 블렌드스페이스를 계속 섞는 방식은 폐기.
저속에서 발이 미끄러지는 문제 있음 → **명확한 상태값 + 이동거리 기반 애니메이션 재생**(Distance Matching)으로 전환.
Walk/Run 사이클 자체는 고정 애니메이션(root motion), 상태 전환 시 Start/Stop 구간만 실제 이동거리에 맞춰 발 위치 매칭.

---

## 2. 경계상태

- **미경계**: 총 내림, 랜덤하게 주변을 돌아보는 연출 재생
- **경계**: 조준 위치값을 이용해서 특정 방향을 고정한 채 옆으로 걸으며 이동 가능. 자연스럽게 30도 범위 시야각으로 주변 경계
- **타겟 조준**: 해당 위치를 계속 조준

조준 방향 고정 + 이동은 표준 밀리터리 슈터 패턴으로 구현:
- 몸통 회전을 "이동 방향" 대신 "조준 방향(에임 Yaw)"에 고정 (Orient to Aim)
- 조준 이동은 (Speed, 몸통 정면 기준 이동각도) 조합으로 **전신 애니메이션**(8방향)을 선택 — 다리만 블렌드하는 게 아니라 총 든 상태 그대로 전신이 움직이는 클립
- 위/아래 세밀한 조준(Pitch)만 AimOffset **애디티브**로 그 위에 얹음 (전신 클립 자체는 그대로, 미세조정 용도로만 — 좌우 방향이나 자세 자체를 애디티브로 만들지 않음)
- 지금 `AimPitch`로 Spine2를 `ModifyBone`으로 직접 돌리는 임시방편은 정식 AimOffset(Pitch 위주) 에셋으로 교체

**미경계 → 경계/타겟조준 전환 시 반응지연 있어야 함** (아래 6번 참고). 적 감지 즉시 스냅되면 안 됨.

## 3. 자세상태

- 일반
- 숙이기
- 엎드리기
- 벽 또는 나무 등에 엄폐하기

## 4. 엄폐 (적 위치값 기반 세부 패턴)

- **벽을 등지고 숙이기** → 다시 돌아서 적 조준 (낮은 벽: 숨어있다가 일어나며 팝업 사격, 다시 숙임 — 반복)
- **벽을 바라보며 숙이기** → 일어나서 적 조준
- **벽 안으로 들어오기** → 기울여서 적 조준 (얇은 엄폐물/나무: 서있는 것 자체가 엄폐, 사격 시 옆으로 lean만)
- **엎드리기**: 엄폐물 없을 때와 동일한 엎드려 사격 자세 유지

### 구현 방향
레벨에 이미 배치해둔 타겟포인트들을 활용 — **`ATargetPoint`를 상속받은 커스텀 클래스**(예: `ACoverPoint`)를 만들어서, 각 포인트 인스턴스마다 에디터에서 값 입력:
- 엄폐 타입(위 4가지 패턴 중 하나)
- 등지고 숙이기/바라보고 숙이기일 때 회전 방향, 기울임(lean)일 때 좌/우 방향
- 노출(팝업/기울임) 지속시간 범위, 재엄폐까지 쿨다운 범위 (아래처럼 랜덤화)

팝업형(벽 등지고 숙이기, 벽 바라보고 숙이기)은 **Ducked → Exposed(사격) → Ducked** 반복하는 작은 서브 상태머신 필요.
로봇처럼 일정 주기로 반복하면 티 나니까 노출시간/쿨다운을 프로필당 min~max 랜덤 범위로.

## 5. 관성 (이동/회전)

목표 **위치값만 받으면 그쪽으로 스스로 조향**하는 구조로. `UGVMovementComponent`가 이미 쓰는 패턴을 그대로 재사용:
- 조향: `SteerInput`을 목표로 즉시 스냅하지 않고 `MaxSteerChangeRatePerSecond * DeltaTime`만큼 프레임당 델타 제한
- 가속: `SmoothedThrottleForce`도 `MaxThrottleForceDelta`로 동일하게 델타 제한
→ 캐릭터의 몸통/시선 회전, 이동 가속·감속에도 같은 클램프 방식 적용

- 회전각이 큰 경우(예: 90도 이상 뒤돌아보기)는 몸통 트위스트 대신 **Turn-in-place 애니메이션** 트리거
- 급선회 시 상체가 살짝 쏠리는 lean 애디티브(각속도 → alpha)로 관성감 보강

### UGV와 동행할 때 추가 로직 필요
같이 움직일 땐 UGV 속도에 맞춰야 함 — **UGV보다 빠르거나 느리면 안 됨** (속도 거버너 로직 필요, 목표위치 조향 위에 UGV 현재속도를 상한/기준으로 얹는 형태).

**기존 버그**: 집결 후 UGV가 출발할 때, UGV 자율주행 경로가 UGV의 최초 출발지점부터 시작이라 뒤쪽 분대원들이 아직 "설 자리"가 안 열려서 몰려 뛰어오는 현상. 시간이 지나 UGV가 경로 포인트를 많이 지나면 뒤쪽에 공간이 생기면서 자연 해소됨.
→ 새 조향 로직 설계할 때 이 타이밍 문제를 반영해야 함. 후보: 아군의 추종 목표점을 "현재 arc-length 오프셋"이 아니라 **UGV가 실제로 진행한 경로 길이만큼만** 열어주는 방식으로 제한 (UGV 출발 직후엔 뒤쪽 목표점도 앞쪽으로 당겨져 있다가, UGV 전진량에 비례해 뒤로 풀어주는 형태).

## 6. 반응 / 개체별 디테일

- **반응지연**: 적 감지 → 조준 시작까지 0.2~0.6초 랜덤 지연, 조준 자체도 관성 있게 보간 (5번 회전 관성과 연결). 명중률이 자연스럽게 낮아지는 부수효과도 있음
- **피격/근접 피탄 리액션**: 맞거나 근처로 총알 지나가면 짧은 움찔/숙임 몽타주
- **개체별 애니메이션 개별화**: 지금 아군들 대기 애니메이션이 전부 싱크되어 똑같이 재생됨 → 개체마다 랜덤 시작 오프셋/시드를 줘서 따로따로 움직이게. 대기모션뿐 아니라 전투 성향(노출시간, 명중률, 반응속도 범위)도 개체별 편차

## 7. 명중률

플랫한 "N% 확률로 miss"가 아니라 **거리/이동중 여부/피탄 직후(suppressed) 여부에 따라 넓어지는 조준 원뿔(spread cone)** 모델.
정지+오래 조준 = 좁음, 이동중/막 엄폐 진입/원거리 = 넓음. 왜 못 맞추는지 시각적으로 납득됨.
RCWS가 주 화력이고 아군 소총 사격은 보조라는 기존 설계 의도와도 일치 (`AllyFormationComponent`가 `FireAtEnemy` 간격을 랜덤화해서 RCWS를 주력으로 유지하는 것과 같은 맥락).

## 8. 분대 시스템

예전에 이런 대형으로 UGV와 함께 기동시켰던 적 있음 — 이걸 정식 데이터 구조로 만든다:

```
        앞
  2분대      1분대
       UGV
  4분대      3분대
        뒤
  6분대      5분대
```

- UGV와 동행하며 1차 집결지점까지 이동할 때: 분대별 상대 위치(위 그리드) 유지
- 1차 지점 도착 후 각자 개인 목적지로 흩어질 때도 분대 단위(약 5명)로 뭉쳐서 이동
- **분대 데이터에 멤버별 경계 방향(watch angle/sector)을 포함** — 이동 중이든 개인 목적지 도착 후든, 분대원마다 담당 경계각을 배정해서 사격선이 서로 안 겹치게

즉 "분대"를 컴포넌트나 헬퍼가 아니라 **데이터(멤버 목록 + 대형 슬롯 + 개인별 경계각)**로 명시적으로 관리하는 구조 추천.

## 9. 사격선(Fire lane) 회피

세 겹으로:
1. **1차(설계/데이터 단계)**: 위 분대 시스템의 개인별 경계각 배정으로 애초에 서로 다른 방향을 보게 해서 겹칠 일 자체를 줄임
2. **2차(런타임 회피, 2026-08-06 수정)**: 원래 "총구를 상하로 미세조절해서 비껴 쏘기"로 설계했는데, 그러려면 전용 애디티브 포즈가 새로 필요함 — 대신 **일시적으로 미경계(총 내림) 자세로 전환**하는 걸로 단순화(기존 Lowered 애셋 재사용, 새 애니메이션 불필요). 사실상 3차와 겹치는 효과라 굳이 나눌 실익이 크지 않음.
3. **3차(런타임 안전망, 이미 구현됨)**: 사격선에 아군이 걸려 있으면 발사 자체를 보류하고 짧은 뒤 재확인(`AllyFormationComponent::IsFireLaneBlockedByAlly`) — 지금은 사실상 이거 하나로 2차 역할까지 겸함.

## 10. 필요 애니메이션 시퀀스 (2026-08-07 갱신 — 최신 상세 내용은 `ally_animation_request.md` 참고)

**레이어드 블렌드 퍼 본 + 웨이트 조합 질문에 대한 답**: 됩니다, 그리고 실제로 이미 이 프로젝트에 그 구조가 있습니다 — `ABP_PlayerCharacter`의 상반신 레이어 5개(Reload/LookAroundRun/LeftArm(정지수신호)/Inspect/몽타주슬롯)가 정확히 이 방식. 다만 0번에서 "레이어링 폐기"라고 한 건 **로코모션(걷기/뛰기)에 다른 파지자세를 얹는 경우**에 한정된 얘기였음 — 발맞춤에 동기화된 전신 움직임이라 위/아래가 따로 놀면 이음새가 보임. **정지 상태(Idle 계열)**나 **순간적으로 얹히는 동작**(사격 반동, 재장전, 둘러보기, 인스펙트)은 레이어링이 정답 — 아래 목록에서 이 기준으로 상당수를 "생략"으로 뺐습니다. 좌우 기울이기(엄폐 린)는 맞습니다, 조합 불가 — 전신이 실제로 기울어지는 별개 포즈라 새로 필요(소스를 못 구하면 스파인 본 하나만 틀어서 직접 만드는 것도 가능 — 아래 "직접 제작" 참고).

Idle 계열(대기/조준대기/숙인대기) 조합 방식: 하반신 순수 Idle 베이스 + 상반신 파지자세(무기 든/내린 — 사실상 전체 교체) + 애디티브로 둘러보기/인스펙트/리로드를 낮은 weight 또는 트리거 시에만 얹기.

"Crouch Aim Walk를 서있는 Aim Walk로 재사용 가능"이라던 판단도 깨진 애셋 기준으로 내린 거라 무효 — 서서/숙여서 각각 따로 요청함. ### 생략 (시나리오 로직 확인 결과 실제로 안 쓰임 / 이미 다른 걸로 해결됨)

- **총구 상하 조절(사격선 2차 회피)** — 9절 수정 참고. "그냥 대기자세로 전환"이 맞는 방향이라 이미 그렇게 단순화했고, 3차(발사 보류, 이미 구현됨)와 겹쳐서 사실상 하나로 통합됨. 애니메이션도 로직도 추가 불필요.
- **Fire/Reload 자세별 개별 클립** — "필수"의 Fire처럼 상반신 애디티브 1개씩(Fire, Reload)만 있으면 Idle-Aim/Crouch-Aim/Prone 어디든 재사용 가능. `AM_Reloading`도 이미 이렇게 쓰면 됨 — 자세별로 따로 안 구해도 됨.

- **Near-miss flinch** — 보류.

### 직접 제작 (구할 필요 없음, 에디터에서 만듦)
