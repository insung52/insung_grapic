## 1. Titan — 4분할 카메라(QuadCamModule) & 상태 정보 위젯(StatusHUD)

### 🎯 목적
전장 시뮬레이션 프로젝트의 군용 차량(Titan 트럭)에
- 운전 보조용 **4분할 카메라 뷰**
- UAV 텔레메트리 형태의 **상태 정보 오버레이**(배터리/고도/속도/방향/GPS/링크/임무/신호 세기)

를 구현하여, 차량 탑승 시 주변 시야와 상태 정보를 함께 제공한다.

### 📋 진행 계획
1. 전/후/좌/우 4방향 `SceneCaptureComponent2D`로 화면을 캡처해 M키로 토글되는 4분할 화면 구현
2. 다른 차량·다른 프로젝트에서도 재사용 가능하도록 **플러그인(`QuadCamModule`)으로 모듈화**
3. 같은 트럭에 동반 기능으로 상태 정보 위젯(StatusHUD) 추가 — 레이아웃은 WBP, 로직/그리기는 C++로 분리
4. 꺾은선 그래프·원형 게이지·컴포스처럼 UMG 기본 위젯으로 안 되는 부분만 Slate 커스텀 페인트로 구현

### ✅ 결과

#### 1) QuadCamModule 플러그인화

| 항목 | 내용 |
|---|---|
| 구조 | `Source/QuadCamModule` (코드) + `WBP_QuadCam.uasset` (Content) 포함 플러그인 |
| 카메라 연결 | `FComponentReference`로 같은 액터의 카메라를 **이름 기반**으로 참조 (`FrontCamera`/`RearCamera`/`LeftCamera`/`RightCamera`) |
| 토글 | `TickComponent`에서 `WasInputKeyJustPressed(M)` 직접 체크 — 별도 Input 바인딩 불필요 |
| 게이팅 | 로컬 플레이어가 **Possess 중인 차량에서만** 반응, Possess 해제 시 자동 OFF |

- 카메라 위치/회전을 코드가 덮어쓰지 않아 **BP 뷰포트에서 드래그로 자유 배치** 가능
- BeginPlay 흐름: `ResolveCameras()` → `SetupCaptures()`(RenderTarget 480x270 생성, `bCaptureEveryFrame=false`) → `CreateAndHideWidget()`(생성 후 즉시 Collapsed)
- 위젯(`UQuadCamUIWidget`)은 `FrontImage`~`RightImage` 4개를 `BindWidgetOptional`로만 선언, 실제 레이아웃은 `WBP_QuadCam`에서 디자인
  - `SetRenderTargets()`는 `FSlateBrush::SetResourceObject()` 사용 — UMG `SetBrushFromTexture()`는 `UTexture2D`만 받기 때문에 `UTextureRenderTarget2D`엔 이 방법이 필요

> **🔧 트러블슈팅 — VRAM 누적 이슈**
> - **증상**: M키를 반복 토글할 때마다 VRAM 사용량이 계속 누적되어 경고 발생
> - **원인**: `bCaptureEveryFrame`을 끄고 켤 때마다 Lumen/TAA 템포럴 렌더 상태(히스토리 버퍼 등)가 매번 새로 할당됨
> - **해결**: 4개 SceneCapture 컴포넌트 전부에 `bAlwaysPersistRenderingState = true` 설정 → 캡처를 멈춰도 템포럴 상태 유지, 재할당 안 함. 불필요한 매뉴얼 `CaptureScene()` 호출 코드도 함께 제거

**새 프로젝트 적용 절차**
1. `Plugins/QuadCamModule` 폴더 복사 (`Binaries`/`Intermediate`는 삭제 후 복사)
2. `.uproject`에 `{ "Name": "QuadCamModule", "Enabled": true }` 추가
3. Generate VS project files → 빌드
4. 대상 Pawn에 SceneCapture 4개 추가 (이름: `FrontCamera`/`RearCamera`/`LeftCamera`/`RightCamera`)
5. `QuadCamComponent` 추가 → 카메라 레퍼런스, `QuadCamWidgetClass = WBP_QuadCam` 지정

- 테스트용 `NextVehicle` 콘솔 명령 구현: PIE 중 `~` → `NextVehicle` 입력 시 레벨의 `UQuadCamComponent` 보유 Pawn을 순서대로 Possess (정식 차량 선택 UI 이전 임시 수단)
- titan_example / TankSim 양쪽에서 동작 확인 완료
- **남은 작업**: `WBP_QuadCam` 디테일 디자인(현재 제목 바 + 2x2 그리드 1차 레이아웃), 카메라 위치/FOV 실제 주행 시야 기준 튜닝

#### 2) 상태 정보 위젯(StatusHUD) 구현

> 플러그인이 아닌 `titan_example` 모듈에 직접 위치되어있음

**파일 구조** (`titan_example/Source/titan_example/UI/`)

| 파일 | 역할 |
|---|---|
| `StatusHUDTypes.h` | `FUAVStatusData` (배터리/고도/속도/방향/GPS/링크/임무/신호 + 그래프 히스토리) |
| `StatusHUDComponent.h/.cpp` | M키 토글, possession 게이팅, 더미 데이터 생성기 |
| `StatusHUDWidget.h/.cpp` | `BindWidgetOptional` 이름 선언 + `UpdateStatus()` |
| `LineGraphWidget`/`RadialGaugeWidget`/`CompassWidget` | Slate 커스텀 그래프/게이지/컴포스 |

- QuadCam과 동일한 패턴: C++ 베이스(`UStatusHUDWidget`)가 위젯 "이름"만 `BindWidgetOptional`로 선언, 실제 트리는 디자이너가 WBP에서 구성
- QuadCamComponent와 동일한 M키/possession 게이팅 — 두 컴포넌트는 서로 모른 채 독립 동작하지만 같은 키를 읽어 항상 같이 켜지고 꺼짐
- **더미 데이터**: `bUseDummyData = true`(기본값)면 사인파 2개 + 랜덤 지터로 값 생성. 실연동 시 플래그를 끄고 `SetStatusData()`(BlueprintCallable) 호출

**커스텀 Slate 위젯 3종**

| 위젯 | 그리는 방식 |
|---|---|
| `SLineGraph` | 배경 박스 + 값 배열을 `MakeLines`로 연결, 색상은 `LineColor`로 WBP에서 지정 |
| `SRadialGauge` | 배경 링 + percent 호(`MakeArcPoints` → `MakeLines`). 중앙 "%" 텍스트는 WBP `Overlay`로 우회 |
| `SCompass` | 원 외곽선 + N/E/S/W 틱마크(고정) + heading에 따라 회전하는 바늘 1개 |

- 세 클래스 모두 `ReleaseSlateResources()`에서 `TSharedPtr<SWidget>`을 `Reset()` — 안 하면 위젯 제거 시 "유출 감지" 경고

**`WBP_StatusHUD`에 배치해야 하는 위젯 이름** (이름/타입 불일치 시 에러 없이 조용히 무시됨, 모두 `BindWidgetOptional`)

| 위젯 이름 | 타입 | 역할 |
|---|---|---|
| `BatteryGauge` | RadialGaugeWidget | 배터리 원형 게이지 |
| `BatteryPercentText` | TextBlock | 배터리 잔량 (%) |
| `FlightTimeText` | TextBlock | 비행/운행 시간 |
| `AltitudeText` | TextBlock | 고도 수치 |
| `AltitudeGraph` | LineGraphWidget | 고도 꺾은선 그래프 |
| `SpeedText` | TextBlock | 속도 수치 |
| `SpeedGraph` | LineGraphWidget | 속도 꺾은선 그래프 |
| `Compass` | CompassWidget | 방향 컴포스 (원 + 틱마크 + 회전 바늘) |
| `HeadingText` | TextBlock | 방향 각도 수치 |
| `GpsFixText` | TextBlock | GPS 고정 상태 |
| `GpsSatText` | TextBlock | 위성 수신 개수 |
| `LinkStatusText` | TextBlock | 통신 링크 상태 |
| `LinkQualityText` | TextBlock | 링크 품질 (%) |
| `MissionStatusText` | TextBlock | 임무 상태 |
| `MissionWaypointText` | TextBlock | 현재/전체 웨이포인트 |
| `SignalDbmText` | TextBlock | 신호 강도 (dBm) |
| `SignalBar1` ~ `SignalBar5` | Border | 신호 세기 막대 5칸 |

**신규 WBP_StatusHUD 제작 절차 (디자이너용)**
1. Widget Blueprint 생성, Parent Class를 `StatusHUDWidget`으로 변경
2. 팔레트에서 RadialGauge/LineGraph/Compass 검색해 배치
3. 위 이름 목록대로 정확히 이름 변경
4. 겹쳐야 하는 항목(게이지+텍스트)은 `Overlay`로 감싸 Center 정렬
5. `BP_TitanTruck`의 `StatusHUD` 컴포넌트 → `Status HUD Widget Class`에 지정

- `UStatusHUDComponent`는 어느 액터에 붙었는지 모르고 possession만 보고 동작 → 트럭 외 다른 Pawn에도 즉시 적용 가능
- **남은 작업**: 실제 텔레메트리 연동(`bUseDummyData = false` + `SetStatusData()` 주기 호출, 위젯 변경 불필요), `WBP_StatusHUD` 실제 디자인, 플러그인화는 보류(필요 시 QuadCamModule과 같은 절차로 승격)

## 2. Grapi-base — Linux(WSL Ubuntu) 빌드 이슈 해결

### 🎯 목적
Grapi-base 엔진의 Linux(WSL Ubuntu) **Desktop** / **Android** 빌드가 정상 동작하도록, 빌드 중 발생한 컴파일 오류 및 스크립트 오류를 원인 분석 후 해결한다.

### 📋 진행 계획
- `./build.sh release`(Desktop), `./build.sh -p android release`(Android)를 WSL에서 순차 시도
- 발생하는 오류를 원인 분석 후, **Windows(MSVC) 빌드에 영향 없는 방식**으로 수정

### ✅ 결과

| # | 증상 | 원인 | 해결 |
|---|---|---|---|
| 1 | Linux+Clang에서만 컴파일 에러 | Filament 자체 테스트 코드 버그 (Linux+Clang 조건부 빌드) | `FILAMENT_BUILD_TESTING OFF` 캐시 강제 설정 |
| 2 | Android 빌드 시 "cmake 3.19+ required" (최신 cmake인데도) | `build.sh` 버전 비교 로직의 major 버전 역전 미고려 | 비교 조건문 수정 |
| 3 | Lua `tmpnam` deprecated 경고 | NDK 툴체인 경고, 빌드엔 무해 | 무시 |

**1) Filament 백엔드 테스트 컴파일 실패 (Linux + Clang)**
```
test_MipLevels.cpp:175:44: error: use of undeclared identifier 'descriptorSetLayout';
did you mean 'Shader::getDescriptorSetLayout'?
```
- `external/filament`은 사내 미러(`code.grapicar.com/engine-dev/core/filament.git`)로 Google 공식 태그를 주기적으로 머지해 받아오는 최신 버전이지만, Vulkan 백엔드를 디스크립터 셋 방식으로 리팩토링하는 중이라 `test_MipLevels.cpp` 일부가 덜 고쳐진 상태
- 이 테스트(`backend_test_linux`)는 `CMakeLists.txt`에서 **Linux + Clang 조합에서만 빌드**되도록 조건이 걸려있어 Windows(MSVC)에서는 드러나지 않았던 문제
- **해결**: `external/CMakeLists.txt`에 `set(FILAMENT_BUILD_TESTING OFF CACHE BOOL "" FORCE)` 추가 (캐시에 이미 ON이 박혀있을 수 있어 `./build.sh -f release`로 강제 재설정 필요). Windows는 영향 없어 수정 되돌림

**2) Android 빌드 cmake 버전 체크 스크립트 버그**
```
Error: cmake version 3.19+ is required, 4.2 installed, exiting
```
- `build.sh`의 비교 로직이 `major < 3 이거나 minor < 19면 에러`로 되어 있어, **major가 3보다 큰 경우(4.2)** 를 고려하지 않고 minor(2) < 19만 보고 거짓 에러 발생
- **해결**: major가 같을 때만 minor를 비교하도록 조건 수정 (major 버전이 더 높으면 통과). Windows는 이 체크 자체가 호출되지 않아 영향 없음, WSL `~/grapi-base/build.sh`에 직접 수정

**3) Lua `tmpnam` deprecated 경고 (무해)**
```
loslib.c:172:3: warning: 'tmpnam' is deprecated: tmpnam is unsafe, use mkstemp or tmpfile instead
```
- Lua `os.tmpname` 구현이 오래된 API를 사용해 NDK 툴체인이 경고만 표시 — 빌드를 막지 않아 별도 조치 없이 무시

> **참고**: Android 빌드도 Desktop과 동일하게 `GRAPI_SKIP_SAMPLES=ON`이 기본 적용되어 `samples/`는 컴파일되지 않음. 켜더라도 Android에서는 `add_demo()`가 실행파일이 아닌 `.so`를 만들기 때문에 폰에서 바로 열어볼 수 없음 — 패키징할 Gradle/Android Studio 앱 프로젝트가 따로 필요하지만, 현재 저장소엔 JNI 브릿지(`android/xeniagear-android-jni`)만 있고 앱 프로젝트는 없음
