이어서 언리얼 엔진 시연 프로젝트에 무인 지상차량(UGV)이 실제 탱크처럼 움직이는 기능을 구현했습니다. 좌우 무한궤도에 각각 힘을 주는 방식으로 물리를 만들어 제자리 회전과 경사면 주행이 자연스럽게 되도록 했고, 목적지를 지정하면 스스로 도로를 따라 찾아가는 자율주행 기능도 함께 넣었습니다. 도로 위를 달릴 때와 벗어났을 때 속도가 달라지도록 지형별 차등 속도도 적용했고, 차량이 맵 밖으로 벗어나면 도로로 되돌리는 안전장치도 만들었습니다.
또한 조이스틱을 연결해 차량과 무인기에 달린 카메라를 상하좌우로 조작할 수 있게 만들었습니다. 조이스틱이 엔진에서 인식되지 않는 문제가 있어 여러 방법을 시도한 끝에 외부 플러그인을 직접 재컴파일해서 해결했습니다. 마지막으로 카메라 화면에 잡힌 차량이나 사람을 자동으로 인식해 네모 상자로 표시해주는 객체 탐지 기능을 구현했는데, 무거운 인공지능 모델 대신 이미 알고 있는 물체 위치를 화면 좌표로 변환하고 가려짐 여부를 판정하는 가벼운 방식을 선택했습니다.

## 교육 내용 (300자 이상)

언리얼 엔진의 물리 시뮬레이션 동작 방식을 집중적으로 공부했습니다. 물체에 힘을 주었을 때 마찰과 무게중심, 공기저항이 어떻게 작용하는지, 그리고 물리 재질 설정값이 실제 움직임에 어떤 영향을 주는지를 직접 값을 바꿔가며 확인했습니다. 처음에는 차량이 거의 움직이지 않는 문제가 있었는데, 원인을 찾아가는 과정에서 엔진이 기본으로 적용하고 있던 마찰값의 존재를 알게 되었습니다.
자율주행과 관련해서는 로봇 분야에서 널리 쓰이는 경로 추종 알고리즘(Pure Pursuit)의 원리를 공부했습니다. 목표 지점을 한 번에 바꾸지 않고 경로 위 조금 앞선 지점을 계속 바라보게 만들면 조향이 부드러워진다는 개념으로, 실제 코드에 적용해 효과를 확인했습니다. 또한 게임 엔진이 이동 가능한 지형을 자동으로 계산하는 내비게이션 메시(NavMesh)의 원리와, 특정 영역에 낮은 비용을 줘서 경로 탐색이 도로를 선호하게 만드는 방법도 함께 익혔습니다.
객체 탐지 기능을 만들면서는 3차원 공간의 점을 2차원 화면 좌표로 바꾸는 그래픽스 투영 수학(뷰 행렬, 투영 행렬)을 공부했습니다. 언리얼 엔진 소스 코드에서 실제 이 계산이 어떻게 이루어지는지 직접 찾아 대조하면서, 문서에 없는 내용은 엔진 내부 구현을 참고해 검증하는 방법을 익혔습니다. 아울러 언리얼의 새로운 입력 시스템(Enhanced Input)이 하드웨어 입력을 여러 계층을 거쳐 전달하는 구조를 배우고, 어느 계층에서 신호가 끊겼는지 단계별로 나눠 확인하는 진단 방법을 익혔습니다.

두 번째로 디자인팀이 준 시안을 기준으로 관제 화면 두 대 분량의 사용자 인터페이스를 전부 만들었습니다. 방위각과 고각, 배율을 보여주는 눈금 리본, 미니맵 위 차량 아이콘과 이동 경로, 시야 범위 표시, 무인기 상태 그래프, 나침반, 신호 세기 막대 등을 각각 위젯으로 만들어 실제 값과 연결했습니다. 위젯 이름만 맞추면 코드가 자동으로 값을 채워주는 구조로 만들어 디자이너가 별도 작업 없이 화면을 편집할 수 있게 했습니다. 포탑 3D 모델을 별도 공간에서 촬영해 배경을 투명하게 처리한 뒤 화면에 겹쳐 보여주는 기능도 구현했습니다.
마지막으로 외부에서 구매한 M1A2 탱크 모델에 지금까지 만든 주행과 사격 기능을 옮겨 붙이는 작업을 진행해, 완성도 높은 3D 모델 위에서 동일한 기능이 동작하도록 했습니다.

## 교육 내용 (300자 이상)

언리얼 엔진의 UI 시스템 구조도 깊이 공부했습니다. 화면에 직접 선과 도형을 그리는 저수준 렌더링 계층(Slate)과, 디자이너가 마우스로 배치하는 상위 계층(UMG)이 어떻게 연결되는지를 이해하고, 직접 그리는 방식의 커스텀 위젯을 만들어 디자이너가 편집 화면에서 바로 쓸 수 있게 하는 패턴을 익혔습니다. 이 과정에서 화면 확대 배율에 따라 선 두께가 어떻게 계산되는지, 편집 화면의 값 변경이 언제 실제 화면에 반영되는지 등 엔진 내부 동작을 소스 코드로 확인하는 습관을 들였습니다. 색이 층층이 끊겨 보이는 밴딩 현상을 GPU의 정점 색상 보간을 이용해 해결하는 방법도 함께 배웠습니다.
또한 언리얼의 차량 물리 시스템(Chaos Vehicle)이 바퀴, 서스펜션, 엔진 토크를 어떻게 계산하는지 공부했습니다. 설정값 이름만 보고 짐작하지 않고 엔진 소스에서 그 값이 실제로 어디에 쓰이는지 추적해 확인하는 것이 중요하다는 점을 배웠고, 실제로 조향이 전혀 빨라지지 않던 문제의 원인이 예상과 전혀 다른 설정값에 있었다는 것을 이 방법으로 찾아냈습니다.

가장 인상 깊었던 것은 오류 없이 조용히 잘못 동작하는 문제의 무서움이었습니다. 나침반이 반대 방향을 가리키던 버그는 기준점 하나만 맞으면 겉보기에 정상이었고, 리눅스 성능 문제도 창은 멀쩡히 떠서 아무도 이상을 눈치채지 못했습니다. 한 번 "완벽하게 고쳐졌다"고 확인했던 것이 특정 조건에서만 성립했다는 것을 나중에 발견한 경험도 있었습니다. 이후로는 검증할 때 조건을 의도적으로 극단까지 밀어보고, 가능하면 독립적인 다른 방법으로 교차 확인하려고 합니다.
직접 만든 로직이 잘 검증된 표준 알고리즘을 이기기 어렵다는 것도 배웠습니다. 병력 회피 로직을 손으로 짰다가 여러 명이 얽혀 도는 문제를 겪고 엔진 내장 알고리즘으로 교체하면서, 이미 검증된 것을 쓰고 그 원리를 정확히 이해하는 편이 낫다는 판단 기준이 생겼습니다.
아직 부족한 점이 많습니다. 특히 렌더링과 네트워크 분야는 이번에 문제를 풀면서 필요한 만큼만 익힌 수준이라 체계적으로 다시 공부할 계획입니다. 앞으로도 원인을 끝까지 확인하고 근거를 남기는 방식으로 일하겠습니다.

## 향후 계획(취업/진로 계획) (500자 이상)

이번 실습을 마친 뒤 같은 기업에서 2학기 장기 현장실습을 이어서 진행할 계획이며, 소속은 엔진개발팀을 희망하고 있습니다. 이번 학기에는 회사 자체 그래픽 엔진을 여러 플랫폼에서 직접 빌드하고 최신 버전으로 업데이트하며 정적분석으로 코드 품질을 개선하는 작업과, 언리얼 엔진 기반 무인체계 시연 프로젝트 개발을 함께 경험했습니다. 두 가지를 모두 해보면서, 엔진을 가져다 쓰는 쪽보다 엔진 자체를 만들고 다듬는 쪽에 더 흥미와 적성을 느낀다는 것을 분명히 알게 되었습니다. 특히 문제의 원인을 찾다가 결국 엔진 소스 코드를 열어보게 되는 경우가 반복되면서, 렌더링 파이프라인이나 물리 시뮬레이션이 내부적으로 어떻게 구현되어 있는지를 직접 다뤄보고 싶다는 생각이 커졌습니다.
장기 현장실습 기간에는 이번에 필요한 만큼만 익혔던 부분을 체계적으로 보완하려고 합니다. 그래픽스 이론과 렌더링 파이프라인, 셰이더, 색공간과 톤매핑처럼 이번에 실제 문제를 통해 처음 접한 주제들을 기초부터 다시 공부하고, 플랫폼별 그래픽 API의 차이와 성능 최적화, 프로파일링 방법도 더 깊이 익힐 계획입니다. 이번에 리눅스 배포 환경의 성능 문제를 추적하면서 그래픽 스택과 프로파일링 도구를 다뤄본 경험이 특히 재미있었기 때문에, 이 방향으로 역량을 더 쌓고 싶습니다. 아울러 이번에 경험한 멀티플랫폼 빌드와 정적분석, 코드 품질 관리 업무도 계속 맡아 엔진 코드 전반에 익숙해지는 것을 목표로 하고 있습니다.
졸업 이후 진로에 대해서는 이 회사에 정식으로 입사하는 방향을 매우 긍정적으로 생각하고 있습니다. 자체 그래픽 엔진을 직접 개발하고 여러 플랫폼에 대응하는 회사는 많지 않다고 생각하며, 이번 실습 기간 동안 실제 제품에 반영되는 업무를 맡아볼 수 있었고 궁금한 점을 물어보면 충분히 설명해주시는 팀 분위기에서 배우는 것이 많았습니다. 장기 현장실습을 통해 엔진 코드베이스와 개발 프로세스에 충분히 익숙해진 뒤, 입사해서도 바로 실무에 기여할 수 있는 상태로 이어가는 것이 현재의 목표입니다.
