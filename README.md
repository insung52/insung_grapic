# raw_reports — 직원별 주간 보고 (프로젝트 무관)

직원이 **"이번 주에 한 일"** 을 프로젝트로 나누지 않고 그대로 적는 곳.
프로젝트 분류·진척 반영은 **각 에이전트가 자동으로** 수행한다.

## 구조

```
raw_reports/
  EMP-001(KJY)/   ← 김준영
  EMP-002(SJH)/   ← 신정훈
  EMP-003(YJS)/   ← 유지성
    2026-W22.md            ← 주간 보고 본문
    2026-W22/              ← (선택) 같은 주차의 이미지·첨부 사이드카 폴더
```

- 폴더명: `EMP-NNN(이니셜)` — roster `_roster.md` 의 ID 와 1:1.
  이니셜 매핑: KJY=김준영, SJH=신정훈, YJS=유지성.
- 파일명: `YYYY-Www.md` (ISO 8601 주차). 이름·프로젝트 코드 안 붙임 — 폴더가 이미 사람을 가리킴.
- 첨부: 같은 주차 폴더 `YYYY-Www/` 에 이미지/영상. 본문에서 파일명으로 참조.

## 작성 원칙 (직원용)

1. **프로젝트로 나누지 말 것.** 한 주에 한 일을 시간순/주제순으로 그냥 나열.
   어느 프로젝트(P1~P5)에 속하는지는 에이전트가 판단한다.
2. 항목마다 상태를 드러내면 분류 정확도가 올라감: 완료 / 진행중 / 막힘(블로커).
3. (선택) 특정 프로젝트로 명시 귀속하고 싶으면 `[P2]` 처럼 태그를 달 수 있음. 안 달아도 됨.
4. (선택) 할당 비중을 직접 지정하려면 `[ALLOCATION] P2 70%, P4 30%` 한 줄. 없으면 보고량 기반 자동 추정.

## 에이전트가 읽는 방식

- **people-status**: 전 직원 `raw_reports/EMP-*/YYYY-Www.md` 를 읽어 각 일감을 프로젝트로 분류 →
  할당 % 자동 계산 → roster/EMP AUTO 섹션 + `projects/P?/assignments.md` 갱신.
- **5개 기술 자문 세션** (graphics-engine, physics-simulation, digital-twin, simulator, demo-production):
  전 직원 보고를 스캔하되 **자기 프로젝트에 해당하는 항목만 추출**해 분석. (데모 세션은 횡단 참조 허용)
- **program-manager / resource-manager / finder**: 통합·인력 분석·검색 입력으로 참조.

## 이력 메모

- 2026-W22: 기존 `projects/P?-*/reports-P?-*/` (프로젝트별) → 본 구조(직원별)로 이관.
  김준영 W17/W18 은 당시 P1(자체 그래픽스 엔진)·P5(디지털 트윈 데모) 양쪽에 분리 제출되어
  `-P1`/`-P5` 접미사로 보존. 그 외 파일명은 원본 유지.
